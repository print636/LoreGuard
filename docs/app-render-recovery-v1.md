# 页面渲染错误恢复 V1

## 适用范围

本阶段为 React 应用增加顶层错误边界。已经启动的页面在组件渲染、React 生命周期或路由懒加载模块失败时，不再只留下空白画面，而是展示固定的恢复界面。

- 页面明确说明显示失败，以及尚未保存的正文、备注或资料修改可能丢失。
- 唯一恢复操作是作者手动点击「重新加载页面」。不自动刷新、重试原组件、重新提交保存/导入，也不启动模型调用。
- 刷新保留当前地址。曾提交的保存、导入或分析可能仍已生效或正在运行，恢复后应先核对状态，避免重复操作。
- 不承诺从崩溃中恢复未保存字段，也不改变现有标签页正文/备注暂存政策。

这是页面显示恢复机制，不是剧情审查质量或后端任务恢复功能。

## 错误内容与安全边界

错误边界只保存 `failed` 布尔值，不保存或显示异常对象。标题、说明、风险提示均为固定简中文案。

安装的 React 19 `RootOptions` 支持 `onCaughtError`、`onRecoverableError` 和 `onUncaughtError`。安装源码的默认 caught 回调会把原异常传给 `console.error`，因此入口显式替换为不读取参数的安全处理。recoverable 回调同样不读取或输出异常；未被边界捕获的根渲染错误则在 React 清空失败树后用原生 DOM 展示相同固定文案的恢复界面。最后兜底不调用 `root.render()`，避免恢复组件自身失败时无限重渲染。

实现不读取 `error.message`、`stack`、`componentStack`、组件 props 或私密原文；不记录到 console、浏览器存储或外部采集系统。没有新增生产调试参数或故障触发入口。

此机制不拦截所有浏览器/网络日志，也不负责事件回调、独立异步 Promise、脚本执行前的首屏 JS/CSS 加载失败、服务器错误或浏览器整体崩溃。这些情况不能外推为本错误边界已覆盖。

## 界面与可访问性

沿用 `design-system/loreguard/MASTER.md` 的星轨书斋语义色板、安静实色按钮和字体，不复用「开始校验」专属彩色渐变。装饰书本采用隐藏于辅助技术的 SVG。

恢复页使用 main/h1/h2 结构、错误提示 `role="alert"`，进入后聚焦主标题，按钮可键盘操作并有可见焦点。页面自身可滚动，窄屏操作按钮占满可用宽度；没有背景粒子、闪烁或等待动画，减少动态效果模式禁用按钮过渡。

## 验证

- 窄单元测试：实际 TSX 边界状态切换与固定 fallback 标记、三类 React 回调对不可读取的合成异常、主入口接线，以及原生 DOM 最后兜底的固定内容、聚焦与手动恢复语义。
- 单元中的服务端渲染只检查恢复页输出，不声称验证服务端 ErrorBoundary 捕获能力。
- 实际浏览器捕获可在生产 preview 中仅通过测试侧拦截路由懒加载 JS 模块制造失败，验证恢复页及按钮；不向应用增加 debug/fault 入口。
- 生产构建通过；集中 Mock 浏览器流程验证了懒加载组件失败后的固定恢复页、异常不回显、无自动写入、键盘手动重新加载及原路径恢复。1440 与 375 实际视口截图已检查。计数与最终 CI 见[当前阶段记录](current-stage-status.md#验证记录)。

本阶段不读取真实账户数据，不访问人工封闭测试材料，不调用模型。
