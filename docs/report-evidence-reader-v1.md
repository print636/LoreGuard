# 报告证据上下文阅读 V1

状态：已实现并完成本地阶段验证，2026-10-02。人工封闭评测仍等待真人标注；本阶段不改剧情判定、
Prompt、标注口径或模型配置，不运行封闭测试集。

## 作者任务与边界

作者读到报告摘录后，需要确认前后发生了什么，尤其是谁在做什么、此前是否有解释。
本阶段补齐“打开报告证据 → 阅读该次分析冻结原文 → 返回原审阅位置”的只读流程。

- 正式问题、角色审查线索、未验证模型提案分别提供阅读入口，展示与计数仍严格分开。
- 阅读不能替作者判断、反馈、修订或发布；原文定位可核对不意味着剧情结论已获验证。
- 不将当前稿、当前资料身份或当前角色候选替换进旧报告的原文阅读。
- 本期不增加正文编辑、搜索、当前稿对照、AI 复核引用跳转、角色档案或复检对比入口。

## 阅读体验

每处摘录提供“查看分析时原文”。报告内只读对话框沿用书斋设计令牌与安静正文，
显示运行、文件、冻结版本、原始行号和引用范围。初次读取从引用前最多 12 行开始，
每页 120 行；可翻页与返回引用位置，不一次下载整篇正文。

对话框支持键盘阅读、Escape 与关闭按钮，关闭后恢复触发按钮焦点；报告筛选、选中
问题和未提交备注不因阅读清空。项目、运行或页面切换立即关闭并清除旧原文，迟到
响应不能覆盖新的阅读选择。正文和摘录不写入地址栏、浏览器存储或客户端日志。

固定头持续显示冻结版本、来源与正式问题/待复核/未验证类别，正文滚动后也不丢失
来源提示。加载或错误期间不编造版本；仅摘录时明确标注。

## 服务端来源解析

`GET /api/v1/analysis-runs/{run_id}/evidence-preview`

- `kind`：`issue` / `review_clue` / `provisional_clue`
- `item_id`：报告条目身份；`evidence_index`：证据序号，模型提案只接受 0
- `offset`：可选，原文行的零基偏移；`limit`：默认 120，最大 200

客户端只提交身份和分页参数。服务器核对工作区、运行、条目类别和证据序号，再解析
冻结来源，不接收任意文稿或原文作为定位证明。

```text
run: { id, project_id }
reference: { kind, item_id, evidence_index, document_id, document_name,
             line_start, line_end, text }
source: { availability, provenance, source_run_id, document_version,
          content_sha256, char_count, line_count }
lines: [{ line_number, text, is_evidence }]
page: { offset, limit, total, has_more } | null
message: string | null
```

普通证据从 `AnalysisRunInputRow` 读取并核对内容哈希、行区间和原文摘录。
已确认角色特征的基线证据优先按该次运行冻结的特征绑定解析，避免同一文稿后来有
新版本时混淆来源：精确证据、`input_id`、文档版本和哈希均需一致，来源运行也必须
属于同一项目与工作区。

已绑定角色审查的明确 `B`（基线）证据必须匹配该特征的冻结来源，不能因相同摘录
也出现在新版中就回退到新版。明确 `C/G/X/P`（新稿与解释材料）只走本次运行的
输入，不借用旧特征来源。没有角色映射的旧条目保留精确冻结匹配路径。

若已确认特征的冻结摘录可核对，但完整旧输入确实不存在，返回 `excerpt_only`，
`lines=[]`、`page=null`，`source_run_id/char_count/line_count=null`；仅展示冻结摘录，
明确“完整原文快照已缺失”。存在但损坏的来源不当作正常摘录回退。
其他无法核对的快照返回安全的 409；未知或无权限资源统一 404。
200、404、409 使用 `Cache-Control: no-store`，接口不进行数据库写入或模型调用。

## 阶段验证

阶段末集中验证结果：

- 后端新证据阅读、既有文稿预览和版本差异合同：73 项通过；临时数据库、SELECT-only
  断言及禁止 Provider 调用，覆盖版本、来源角色、行号/分页、越权与损坏边界。
- 前端全部单元测试：197 项通过；包含本阶段新增的 10 项证据读取模型测试。
- 浏览器：新增 5 项及既有待复核线索 9 项，共 14 项通过；模拟用户反馈修复固定头
  摘要后，只复跑受影响的 2 项并通过。覆盖三类入口、返回审阅状态、错误重试、仅摘录、
  请求竞态与键盘；360/375/1440 和 812×375 横屏无页级溢出，分页按钮可达。
- 最终 TypeScript/生产构建通过；本地 8080 已重启，健康检查正常，已有报告的只读
  原文读取返回 200/no-store，引用身份匹配。原文内容未打印到验收输出。

模拟用户与 Mock API 仅验证产品行为，不替代真人标注或真实模型质量评测；本阶段
没有调用模型，也不宣称角色 OOC 准确率提升。测试源码可见，不是封闭质量测试集。

## 本机体验

刷新 <http://127.0.0.1:8080>，打开已有完成运行的“完整报告”，在问题或线索的证据
旁点击“查看分析时原文”。翻页、返回引用位置或按 Escape 关闭，继续原位置审阅。
