# 角色 OOC 证据闭环 v2：2026-09-27 开发检查点

本阶段只声称完成了角色漂移结论的证据完整性合同，不声称开放剧情准确率已经通过验收。

## 本阶段变更

- 角色复核模型仍只返回服务端签发的 `B/C/G/X` 编号，不能返回或修改原文坐标。
- 正式问题与模型参与的待复核线索按照模型实际采用的编号，逐项映射回同一次冻结调用的原文区间；问题元数据保存编号、证据角色及结果数组序号的只读映射。
- 若首轮角色复核已通过严格 schema 与引用校验、但事件同一性二审因 Provider、响应、预算或 deadline 失败，待复核线索使用独立的 `first_pass_review_citations_v1` 标记，只展示首轮实际选择的 B/C 原文。它不写入事件独立性或二审结论元数据，也永远不能晋升为正式问题。
- 已完成模型复核若不能无损映射出至少一条基线 B 与一条当前证据 C，则裁决降级、运行标记部分覆盖，不能退回第一条证据生成正式问题。
- 服务器自身形成的单次反向行为线索没有模型引用，继续使用明确标记的双侧最小证据对，不冒充模型引用。
- 非对象轴的重复反向行为使用最多六条、覆盖不同文档与稿件位置的有界候选池。首轮须通过 `independent_event_citations` 精确选择两条 C；只有可能形成正式冲突时，第二个窄范围事件同一性复核才会只读取这两条 C，并独立返回 `different_events / same_event / unclear`。两轮 C 引用必须一致，二审失败或无法确认时只能待复核。
- 同一文档中相距不超过三行的两条 C 还有服务端词面闸：后一条冻结原文必须在行首明确出现受限的时间/场景边界。没有边界时，即使两轮模型都判断为不同事件也会降级。该规则优先避免把连续动作重复计数，但会保守漏掉边界写在句中或未明写的真实独立事件。
- 漂移、对象轴、多事件和事件同一性四种复核 Prompt 都通过同一受限 Provider、共享 Token 预算、总 deadline 和用量记账通道；变体字符串不能绕过白名单。二审协议、Provider、响应或资源失败都会标记部分覆盖，不能回退成正式问题。
- 事件二审只需返回三个字段，使用独立的 384 completion 预留与 4 KiB 响应上限；首轮调用前按两条最大 C 预留二审预算。默认 4000 Token 的漂移预算已用六 C 候选池回归验证可容纳两次调用，避免在首轮付费后才发现二审永远不可达。

## 验证

聚焦回归覆盖角色抽取、漂移判定、阶段接线、对象轴以及运行失败恢复。测试包含：模型引用 `B02/C02` 时不得展示 `B01/C01`、同坐标不同冻结文本不得错误合并、无法解析引用必须失败关闭、独立事件选择字段与实际 C 引用不一致时被拒绝、二审 Provider/引用失败保持线索、二审只读取选中的两条 C、相邻片段即使二审误报也被拦截、明确行首时间边界可以通过、十条候选行为被限制为六条且仍覆盖稿件后部，以及四个复核 Prompt 的精确 Provider 白名单。

缩小二审预留后的当前协议另做了两个已知输入的真实模型 DEV smoke。包含迎新会两句相邻描述与三周后港口事件的三 C 输入，首轮选择 `C01/C03` 并返回 `event_independence=yes`，独立二审返回 `different_events`，最终为 `conflict`；两次逻辑调用总耗时 6.224 秒、保守计费 2909 Token。只有迎新会同一场景两句的输入中，本次首轮直接返回 `event_independence=no`，因此没有浪费二审调用，最终为 `needs_confirmation`；一次调用耗时 3.746 秒、保守计费 2106 Token。此前同一两阶段功能的开发复跑中，首轮曾对该同场样例误报 `yes`，窄范围二审返回 `same_event` 并阻止晋升，说明模型结果存在波动，也说明二审仍不能被外推为通用可靠。行首来源闸只再覆盖明显相邻边界。模型别名不能证明上游实际权重；这些已知样例不是盲测、准确率或跨故事泛化结果。
