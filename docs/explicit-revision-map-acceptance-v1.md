# 显式修订归属集中验收 V1

本轮集中增量审查及浏览器/API 验收已完成，无产品阻断；官方 CI 与最终本机交付另记于阶段状态。本轮没有新模型调用或分析任务。

## 作者任务与范围

作者拿到改名文件或将 Word 内容改为 Markdown 后，明确选中要修订的原文稿。保存后应沿原逻辑名称形成下一版本，不能按新文件名另建一条误认的版本链。界面收据需区分上传文件名与保存后的逻辑名称、版本，旧报告继续读取其冻结原文。

本轮只验上传、归属、版本和复检准备，不启动分析，不把成功上传当成语义修复完成。查询、上传与准备入口均通过普通账户/API；正式数据、旧 QA 副本及旧报告保持不动。

## 精简场景

| 场景 | 输入与操作 | 必须观察的结果 | 覆盖安排 |
| --- | --- | --- | --- |
| 改名 Markdown 修订旧稿 | 新 QA 副本内复用公开 DEV 的 `habit-draft.md` 及既有真实报告，上传另一文件名的 Markdown，明确选中当前原稿 | 同逻辑名称 v+1；收据准确区分两种名称；旧 v1 原文、报告和确认来源不变；资料变化提示可进入复检准备 | 真实浏览器主旅程，桌面与窄屏复用同一次保存 |
| Word 转 Markdown | 仅在新 QA 副本通过普通上传建立一份公开 DEV Word 文稿，再用改名 Markdown 明确修订它 | 保留原 Word 逻辑名称及版本链，新正文按实际 Markdown 文件解析；不凭文件扩展名误判正文或生成另一逻辑文稿 | 定向普通 API；若最终界面复用路径不同，再覆盖该必要交互 |
| 显式旧目标已过期 | 首次修订成功后，使用另一幂等键明确指定已不再活动的旧目标 | 拒绝过期目标，不静默追随新版、不写入额外版本；原操作相同幂等键的合法重放仍应先返回已保存收据 | 真实 API 一次新操作拒绝；重放先于活动检查复用后端专项 |
| 不替换与异步隔离 | 未选原稿、切换原稿/报告，以及迟到上传回包 | 未选不暗中替换；操作身份随目标改变；旧回包不能写入新页面；未知结果仍沿既有安全重试边界 | 优先复用既有专项，仅补新增字段改变的断言 |

Word 对照是本轮上传兼容夹具，不是旧真实模型报告；不会为它建立分析报告或确认特征。正式报告冻结来源的验证由既有 Markdown 主旅程承担。

## 复用与观测

- 复用上一轮公开 DEV QA 数据库的 SQLite 备份，在本阶段独立副本写入；不读取/复制密钥文件，不解密数据库内原有加密字段，临时 QA 登录信息不写日志。
- 本轮包含既有上传收据表的 nullable `import_metadata` 迁移。新 QA 副本必须先走仓库迁移流程，再启动本轮应用；不对源数据库手动 DDL。旧行保持 null、不伪造历史上传名；迁移保留与事务绑定优先复用后端专项。
- 复用已有普通账户驱动、文件上传幂等与收据校验、完整冻结 reader、资料变化/复检准备组件。待新 DTO 稳定后只补显式目标身份与保存名的必要观测，不重建验收平台。
- 每次保存记录上传文件名/字节摘要、显式目标及其原版本、HTTP 状态、保存文档的逻辑名称/版本/正文摘要、是否重放；按来源区分 API 原值与 UI 展示，不修改候选或来源来通过断言。
- 保存前后仅比较本次选定的旧报告、记录、冻结输入和确认来源；核对分析数量不增加。旧大库保护沿已有历史收据，不重复全库扫描。
- 实际保存一次 MD 修订、一次 Word 初次上传及一次 Word→MD 修订，另有原操作重放及一次新键旧目标拒绝。新稿上传不会自动确认资料身份：作者核对新章节为 draft/main 后，才继续材料复检准备。不创建 recheck，也不调用模型。

## 本轮实际结果

- **集中审查**：核对新增 nullable 迁移、显式目标授权/活动版本/原逻辑名、事务内版本及收据、原键重放先于活动校验、旧 null 来源说明、前端严格收据和不自动推断目标。未发现需修改产品的阻断。
- **真实旧 Markdown 报告回流**：普通 QA 账户在新数据库副本中，把改名 Markdown 明确保存为 `habit-draft.md` v2。收据保留实际上传名、Markdown 格式、旧目标 ID/v1、新文档 ID/v2 及被替换 ID；没有建立上传文件名的旁支。原操作重放返回同一个 v2，新操作指定旧 v1 返回 `replacement_target_stale`，不增版本。
- **真实上传格式对照**：在该副本普通 API 上传一份公开 DEV Word，再将改名 Markdown 明确保存为原 `.docx` 逻辑名 v2。正文按 Markdown 实际字节解析、两版本均保留。此 Word 对照没有模型报告，不能称为旧 Word 真实审查报告回流或 Word 排版还原。
- **正常身份与准备步骤**：首次保存的新章节为 unresolved/unknown，材料准备正确返回 `invalid_draft_review_targets`。通过普通作者 API 核对该新章节为 draft/main 后，`inputs_changed=true`、`can_prepare=true`，页面可准备复检；没有点击提交分析。
- **旧资料保护**：旧报告、记录与两侧冻结 reader 相同；定向比较 2 条旧冻结输入、2 条原候选（1 条已确认、1 条待确认）的完整行及摘要均相同。分析任务仍为 38，新增分析/模型均为 0；原 QA 数据库没有迁移或写入。
- **迁移**：仅新 QA 副本走仓库 Alembic 0025→0026，迁移前后 29 文稿、38 分析、71 冻结输入均未变。该真实副本原上传收据为 0 行；旧非空收据、旧 null 兼容及破坏性回退保护由后端专项验证，不冒充真实存量覆盖。
- **浏览器**：3 项新增交互加 4 项受影响已有路径，7 项首批通过，15.0 秒。覆盖显式目标、不发无目标上传、严格收据失败、未知结果锁定/原键恢复、跨项目迟到响应、工作台对应关系及 375 宽显示。无宽泛 API 放行或删除旧行为断言。
- **产物**：使用前端最终 17 份受测资源 `App-DgCfgpLo.js`，未重建；真实后端桌面/375 截图来自该产物。新副本和全部首失败收据保留。

真实旅程共记录 114 次 API 请求，含以下驱动准备停点：将无目标按钮错误预期为 disabled（产品实际点击提示且不 POST）；误以为上传后无需身份核对即可复检、后续只读确认该门仍生效；直接 QA POST 漏传 CSRF 头而被正确拒绝 403。均只调整驱动并沿同一副本接续；已保存稿仅做预定同键重放，未另建版本、未改产品、未绕过身份或 CSRF 验证。登录/CSRF 值只在内存处理，不写收据。

## 集中窗口与交付

后端/前端专项和最终构建稳定后，一次核对归属授权、原名称/版本链、幂等和旧目标并发门、收据与错误展示、迟到响应隔离；问题集中交原所有者合修，仅复核受影响项。既有自动化已经覆盖的细节不在浏览器全排列。

主工作区 14 个用户文件的基线哈希已保存，8787/8317 仅只读核对。验收完成且根文档窗口关闭后，才冻结功能版本、精确发布功能分支并执行一次五项 CI。最终结果文档关闭后再快进主分支；本机沿既有 SQLite 备份/仓库升级安全路径处理该迁移，不能直接照搬上阶段无迁移的启动步骤。安装最终受测资源并必要更新应用一次，网关不操作。条件估算仅本席位验收/交付 3–5 小时，不含开发者专项和构建，不作实际耗时承诺。

本阶段私有证据位于 `artifacts/explicit-revision-map/`：`acceptance-summary.json` 为小汇总，`real-backend-verified/receipt.json` 为实际最终旅程，先前停点各自保留；`browser-first.txt` 为 7 项集中浏览器结果。截图分别记录明确对应关系和正常复检准备状态，不将页面上的历史模型用量说成本轮调用。
