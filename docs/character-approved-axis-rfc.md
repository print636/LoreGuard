# 角色特征“作者批准稳定轴”v1 说明（原设计 RFC）

状态：已实现 v1 轴身份与 0018 作者方向对齐增量（仅 `core_personality`）。历史运行、冻结 Oracle 和此前真实模型评测结果不改写；新增方向流程的跨故事真实模型质量验收尚未完成。方向映射的完整设计与边界见[方向对齐 RFC](character-axis-direction-alignment-rfc.md)。

## 背景与目标

模型从设定中抽取的 `trait_key` 是自由生成的标签。旧版非对象类角色特征主要依靠该标签进行跨文档匹配；同一个行为语义轴可能因措辞不同而漏配。冻结的 `character-ooc-transfer-v1` 严格运行在正式候选选择处失败：霁青的来源锚点候选存在，但模型标签不在预注册的 `(trait_key, polarity)` 允许项中。来源锚点诊断不能代替严格验收，且另有基线不完整、已解释案例误报等独立问题。

目标是让**作者对语义轴的确认**成为稳定、可追溯的项目数据，使模型标签变化不自动改变比较身份；不要求作者批准模型对原文的每个概括，也不让标签相似度取代原文证据。

## 概念和比较边界

| 概念 | 含义 | 身份作用 |
| --- | --- | --- |
| 原文证据与 `value` | 设定/历史中的原句及其最小主张 | 证明候选内容；不可由批准轴反向生成或覆盖 |
| `model_trait_key` | 模型提出的中性语义轴名称，即现有 `trait_key` | 保留为来源和诊断信息；不是新的权威身份 |
| 作者批准轴 | 项目内的轴 ID、中文含义、版本及作者写的不可变正向命题 | 同轴匹配的稳定身份；正向命题只定义判定方向，不表示角色已满足该命题 |
| 原始 `polarity`、作者 `axis_alignment`、换算的 `axis_polarity` | 模型原标签方向、作者核对的同向/反向映射、相对轴命题的方向 | 分开保存；不能从字面褒贬或旧标签自动推断 |
| `key_object` / `comparison_key` | 原文绑定的对象及现有冻结对象键 | 对象边界仍独立生效，不被批准轴吞并 |
| 权威、作用域、发布序号 | 正式设定/已发布历史、分支与生效期 | 继续决定哪条基线可用；批准轴不提升权威 |

v1 使用项目内 UUID、不可变名称与定义，以及不可变的版本 `1`；没有改名、改定义或升级轴版本的接口。只有 `core_personality` 候选可绑定批准轴。`speech_pattern`、`value`、`behavior_boundary`、`current_state` 和 `preference` 暂不使用此轴；它们的对象键、原有比较和证据规则继续适用。情境、叙事分支、角色归属和权威过滤仍是额外条件。语义相关不等于同轴：例如“征询同伴”与“等待上级命令”不能仅凭“路线决策”共享身份。

批准轴只表示“比较什么”，不预判新稿是否矛盾。草稿观察仍须原文证据、角色行为归属、方向和对象校验；证据不足时弃权或要求作者确认，不靠轴 ID 输出问题。

## 已实现的存储、审核与版本

项目级 `character_trait_axes` 保存轴 ID、`core_personality` 维度、名称、定义及其 SHA-256、版本 `1`、创建者和时间；0018 另存作者写的正向命题、哈希、填写者与时间。旧轴可由作者一次性补写命题，命题写入后不可在原轴改动。同一项目中规范化后定义完全相同的轴不能重复创建。候选行和附加审核记录分别保存批准轴 ID/版本、同向或反向映射及相对轴命题的方向；模型原始 `trait_key`、候选证据、`value`、`polarity`、`comparison_key` 和候选指纹保持原样。创建轴、审核命题与确认候选是不同的显式操作；确认候选时，轴绑定、作者方向映射与审核记录在同一事务中写入。服务端校验项目/工作区归属、CSRF、候选修订、来源是否过期、轴维度/版本/命题哈希和审核幂等键；模型不能自行批准或绑定轴。

后续新分析的已确认角色快照冻结原始标签、批准轴 ID/版本、名称、定义及定义 SHA-256，还冻结正向命题、其哈希、作者映射和轴方向，同时保留对象键、原始方向和来源/权威/作用域；这些字段纳入新快照哈希。无轴的旧快照 payload 和哈希保持不变，既有运行和报告不回写。跨项目不能引用轴。新候选确认时的同轴冲突仍须通过原有作用域和发布范围校验，并使用经作者审核的轴方向；显式替代只有在轴一致且满足原有替代条件时允许。当前没有轴版本升级或给原本无轴的已确认旧候选补绑入口。

## 旧数据兼容

没有批准轴的旧候选和旧运行快照继续按既有逻辑处理；迁移字段保持 `NULL`，不从 `value`、旧 `trait_key` 或证据中猜测回填。已确认但只绑定 v1 轴的旧候选仍是正式特征，不过方向标为 `legacy_unverified`；新运行对它的同轴方向判断弃权并显示部分覆盖，作者可在角色档案逐条补认，原确认与历史报告不改写。API 仍接受不带轴的旧式确认请求；新页面要求待确认核心性格候选先选或创建轴，并显式核对方向。无轴候选不能暗中与已批准轴候选合并或替代。

## 作者体验

在项目的角色工作台运行正式资料基线后，打开人物的“待确认归纳”，先核对原文证据、反向证据、模型原始标签、方向、对象、权威和发布范围。核心性格候选可选择项目中已有轴，或填写名称、定义及正向命题、先创建轴；随后作者明确选同向/反向再单独确认。不确定时保持待审，不自动选择。旧轴缺命题可先补写；旧已确认绑定的方向可在角色档案展开原文证据后逐条补认。项目轴列表分页加载；列表未核对完整时页面暂不允许新建轴。创建成功本身不确认候选，也不会改写已有报告。驳回候选无需选择轴。同轴冲突、过期候选、版本/命题变化等由 API 拒绝并提示刷新或核对。当前没有相似轴自动推荐、批量审轴或无轴旧候选的事后补绑。

## v1 已实现的链路与后续测试

1. 已接入项目轴表与迁移、分页读取及创建 API、候选原子确认绑定和角色工作台审轴界面。
2. 新运行冻结批准轴身份与定义；定向抽取将轴定义作为模型比较提示。模型返回的记录不得携带轴 ID；只有单一目标、经原文和角色校验通过的定向记录才由服务端绑定轴。不同原始 `trait_key` 可以经这一路径归于同一批准轴，原标签仍保留；主抽取记录不会因标签相似而自动绑定。
3. 同一角色、文档和来源行若在两个批准轴的定向结果中被复用，视为歧义并弃权；部分覆盖或模型失败继续显示为 `partial`/待确认。方向、行为归属、对象、分支、情境、例外和成长桥梁仍按原证据门槛复核。
4. 单元和接口回归负责验证迁移、快照、审核边界、同轴不同原标签及双轴证据弃权。还需另建**首次运行前冻结**、跨故事的人工标注材料和独立真实模型全流程测试；现有开发者可见 Demo 与旧严格迁移集不能代替这一验收。

公开 API：`GET /api/v1/projects/{project_id}/character-trait-axes?limit=100&offset=0` 分页读取；`POST /api/v1/projects/{project_id}/character-trait-axes` 以名称、定义和正向命题创建轴；`GET /api/v1/projects/{project_id}/character-trait-axes/{axis_id}` 精确读取；`POST .../{axis_id}/positive-proposition` 给旧轴一次性补定义。候选确认 `POST /api/v1/projects/{project_id}/characters/{character_key}/profile-candidates/{candidate_id}/decisions` 在原字段外需提交 `axis_alignment=same|opposite` 与预期命题哈希；旧已确认绑定使用同一候选下的 `/alignment` 操作补认。审核可选 `Idempotency-Key`，所有写入都属于当前登录工作区并需 CSRF 校验。

## 评测边界

`character-ooc-transfer-v1` 的 Oracle、正文和首次运行前冻结的哈希不修改；其严格选择器要求**模型原始 `trait_key` 精确命中预注册选项**。作者批准轴是不同的产品流程，不能把来源锚点确认或作者改轴冒充为该严格门槛通过。旧严格失败报告仍保留；旧材料可用于开发回归，但只能标为开发者可见诊断。

为衡量新流程，应在首次运行前另行冻结新材料、人工标注的角色—轴—对象—方向、作者审核协议、预期问题及证据、评分脚本和哈希。报告至少分别给出候选召回、轴绑定正确率/待确认率、草稿观察覆盖、问题误报/漏报、材料覆盖与成本，并执行多次独立全流程运行；部分运行或人工补救单列，不汇入自动通过率。若测试者已见材料，明确标注开发者可见，不能声称盲测或开放文本泛化。

## 风险与待定决策

- 人工审轴有成本；若默认替作者确认，原有自由标签漂移会换成错误合并。先测真实审核耗时，再决定是否加入带置信度的批量建议。
- 轴定义过宽会误报，过窄会漏报。建议用项目内轴 ID 和中文定义，而非仅存一个可变英文字符串；模型只提议，作者决定。
- 含糊设定可能没有可靠语义轴。允许“不确定/暂不建立基线”，不要为了提升覆盖率强制归类。
- 后续决策：是否提供既有已确认候选的显式补绑、轴版本升级和批量审核；这些均不属于 v1，也没有自动迁移行为。
