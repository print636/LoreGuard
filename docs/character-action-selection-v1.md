# 固定原文窗口内的模型行为选择

本功能改善角色深度审查的候选发现：有些动作没有使用预先列出的动词或否定句式，仍应有机会进入核实。选择行为与判断冲突是两个步骤；模型找到一段可能相关的动作，不代表该动作已证实，更不代表已经违反角色设定。

首版用于作者已确认、具有明确适用情境的行为习惯，例如“正式演出开场前逐支试音”。它不是对所有性格、偏好和价值观维度同时更换抽取方式。

本文描述功能合同，具体受测版本、真实调用结果和未完成项见[当前阶段状态](current-stage-status.md)。

## 怎样工作

当某个角色目标需要补充抽取时，在一次既有抽取调用中启用新选择方式：

1. 服务端从本次冻结文稿建立有限的原文窗口，提供角色、比较目标和可引用的分句标识。首版每个窗口限同一句内最多三个分句。
2. 模型最多选择两个行为，返回行为所在分句、人物起点及连续承接路径；也可以返回没有候选或不确定。候选生成不要求命中特定动词或“未……就……”句式。
3. 服务端核对所选位置是否属于该次原文、人物目标和允许范围，并从原文重建候选。引用不存在、跨出范围、顺序错误或超过数量限制时，不接纳该选择。
4. 选择结果进入独立的语义核实。模型需要判断动作是谁做的、是否实际发生、物件是否同指，以及与角色特征的关系；来源和引用仍由服务端核对。
5. 通过核实的观察进入已有的去重、保存和主审流程。最后仍需结合设定、适用情境与解释材料决定是否形成正式问题。

新协议的来源核验直接核对冻结原文和选择路径，不再要求候选先由旧动词规则枚举出来。完整物件描述和有依据的省略承接应保留；不通过删掉限定或替换原文来凑出可接受的证据。

## 覆盖和未决材料

找到一个行为，不说明窗口内所有相关行为都被找到。没有候选、模型不确定、材料被截断或调用没有完成时，继续保留相应的覆盖限制。

选择结果本身不证明先前某条归纳已经被核实，也不因为只返回一个候选就获得“唯一对应”的资格。原缺口能否解除，仍须满足[原主张复核合同](character-claim-resolution-v1.md)。后续已有完整有效核实依据时，沿用原来的恢复规则，不额外设置永久未决状态。

## 授权、兼容和开销

作者仍在每次发起审查时选择是否开启角色深度审查。新运行保存本次能力选择；旧任务重试没有新标记时，继续原处理方式。客户端不能凭一个私有开关开启模型能力。

运行通过 `batch_coverage.habit_action_selection_policy` 保存 `habit-action-selection-v1`；实际调用还需通过服务端既有账户、深度审查和短动作链授权。新选择器与 V16 独立核实使用各自明确的提示词与调用边界。V16 不携带先前归纳的身份，不能由它声称原归纳已经得到同义核实。

选择调用替换一次既有的目标补充抽取，后续复用独立核实，不另加 Agent 或一层常驻模型循环。请求仍使用账户模型配置，受到原调用次数、剩余 Token、时限与取消检查约束。格式错误、预算不足或模型无可用回复时保留可解释的未完成状态，不把失败当成无冲突。

这一阶段不扩展任意跨句、长距离指代或大篇幅处理，也不新增作者必填项。

## 怎样验证

受控测试分别检查来源与路径约束、合理省略、预算与历史兼容。真实试用使用与人工封闭集隔离的正常作者稿，关注行为是否进入核实、完整原文能否打开、主体和用途是否被正确区分，不把必须生成正式冲突作为通过条件。

每次真实试用记录是否实际触发新选择器。若常规抽取已经完成审查，没有进入这条补充路径，只说明该次正常流程的结果，不能算作新选择器验证成功。选择、核实、最终接纳与数据库保存分别记录；保留首次失败，不用重复采样挑选好结果。
