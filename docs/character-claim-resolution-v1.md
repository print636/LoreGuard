# 原主张复核与目标覆盖恢复

本功能处理一种审查停滞：第一次抽取的一条归纳未通过核实，后续已经从原文接纳了同一目标的行为，但系统仍保留第一次的材料缺口。两次文字相似、位于同一行，均不足以说明缺口已经解决；需要把原归纳、核实依据和最终接纳的观察连接起来。

本文描述实现合同。每个版本的真实试用、未完成判断及工程检查结果见[当前阶段记录](current-stage-status.md)，不能用实现合同代替质量成绩。

## 怎样处理原来的缺口

1. 第一次抽取结束后，在本次工作进程内保留有可靠出处、可以继续核实的原归纳，以及它对应的冻结文稿和比较目标。原归纳不通过改写来变成另一条更容易接受的话。
2. 后续接纳的观察若有完整记录，能精确对应同一来源、原归纳及目标，直接使用这份核实依据。仅有相同人名、行号、物件或接受数量时，不建立这种对应。
3. 若后续采用了另一种表述，已有相关观察只能说明值得继续核实。系统可对原归纳再做一次有界复核，仍使用既有的主体、实际行为、物件和原文引用核验。每个确认目标在一次运行中至多安排一次这样的复核机会；原有的有限结构纠正或传输重试仍受预算和时限约束，按实际发生计量，不能将一次复核机会当成物理 HTTP 次数。
4. 核实通过的观察进入正常的接纳、去重、快照和主审流程。只有最终确实接纳的观察可以支持清除对应缺口；模型单独返回“支持”不够。同一个行为的多个表述也不因此变成多次独立事件。
5. 某个目标涉及的原缺口已完整列出、逐条解决，且没有未知、截断或遗漏时，才能恢复该目标的最终材料覆盖。其他人物、目标及尚未处理的部分保留原状态。

原主张复核沿用已启用的短动作链核验能力。它没有扩大到任意跨句或长距离指代，也没有增加新的正式冲突判定标准。是否形成正式问题，仍由原有主审、情境和解释证据共同决定。

短动作链里的物件证据保留完整来源词组，例如“新送来的救生衣”，不要求动作摘要再重复写出“救生衣”才能核实。来源词组允许数量和修饰语，但必须完整保留原物件及其限定，不能将“救生衣的标签”等另一个受事替代为救生衣；模型的同指判断、逐步主体及实际行为核实仍须通过。这个修复不增加调用，也不扩大到任意同义词或长距离承接。

## 哪些情况继续保留未决

- 原归纳无法可靠定位、原文或版本不一致。
- 原归纳与后续观察的关系不能确认，或原主张复核仍拒绝、弃判、无法形成完整依据。
- 仍有未列明、未处理或超过保存上限的材料；一个成功观察不能代表所有材料均已核实。
- 当前阶段剩余额度不足、调用超时、任务取消或没有取得可用回复。
- 其他比较范围、解释、发布状态或设定权威仍不明确。

“最终仍未解决的原因”和“过程里曾经失败的原因”分别保存。若有效的后续核实已将问题缩小到物件指代，报告应说明物件尚未核实；无法确定具体原因时使用一般提示，不继续误称人物归属未确认。

## 原调用记录与最终状态分开

最初那次抽取的失败和部分覆盖记录保留。恢复某个目标的最终覆盖，不会把过去的模型调用改写为成功，也不代表整篇文稿已完成审查。报告中的正式问题、待复核线索和整稿覆盖提示各自保留含义。

作者不需要填写额外字段。新建审查时，主动勾选“角色深度审查”后，符合条件的任务会保存本次能力选择。旧任务重试使用原冻结选择；未开启深审时不触发这项新增复核。请求使用原任务的模型账户与计量，受剩余预算、调用时限和取消检查约束。

## 内部来源记录

运行在 `batch_coverage.claim_resolution_policy` 保存 `claim-resolution-v1`。实际执行还须通过既有角色深审与短动作链的服务端授权，客户端不能自行打开私有能力。

私有诊断子载荷 `claim_resolution_v1` 记录原归纳摘要标识、核实请求与提案、已确认设定、冻结来源、最终观察及目标覆盖范围之间的关系。原模型归纳正文仅用于当前进程里的复核，不把原始模型回复或凭据附进这些记录。

落盘前再次核对来源、目标、已确认设定和实际观察。坏记录不能通过删除诊断附件、保留晋升结论的方式绕过检查。普通诊断响应与报告导出不暴露这份私有载荷；作者继续使用现有报告和原文阅读入口。旧报告没有这种记录时保持原来的含义，不补造历史关联。

实现使用现有分析诊断与观察快照，不新增数据库表。公开开发稿的独立验收可以另外记录必要的安全字段来核对这条链，但不会读取人工封闭集进行调参。
