# 主抽取跨任务真实模型核验（2026-09-23）

这是一次**开发者编写、非盲测**的跨任务诊断：把已冻结的 Evidence Investigator 原创双文档夹具用于主模型抽取链路，观察格式失败、证据拒绝和最终问题。它与 [三文档格式小样本](extraction-format-pilot-20260923.md) 的世界观不同，但不是新的人工盲测集；这套 holdout 此前已用于 Investigator 评测，不能再称为未见样本。结果不能外推至开放小说、游戏剧情或生产准确率。

## 执行边界

- 配置：本地 Docker API/worker，账户级 OpenAI-compatible Provider；请求使用的模型别名为 `deepseek-v4-pro`。别名不证明上游实际模型权重或版本。
- 路径：`scripts/run_extraction_cross_task.py` 只把每例的 `canon.md`、`chapter.md` 传入 `AnalysisPipeline(ModelEnhancedExtractor(...))`；预期标签只在输出后用于本地判分。每例独立运行，不跨案例共享故事状态。
- 判分：正例需同时匹配预期问题类别与**完整证据文档、起始行集合**；负例要求最终零问题。运行完成、模型参与、无效记录与失败分块单独报告，不能把降级产生的零问题当成模型主动弃答。
- 安全：运行器不输出密钥、端点、故事正文或原始模型回复；诊断只记录固定类别计数。主抽取的记录级错误与致命的 envelope/归属/证据区间错误分开，`record_rejections` **不是**所有 `invalid_records` 的分解总和。

这次运行前已冻结所用 Prompt、规则和配置；dev 与 holdout 之间没有依照结果调整这些内容。**不使用 H04/H08 的结果反向调参，然后对同一 holdout 重测并称为独立验证。**如果后续针对这两类现象改进，需先在开发样本和通用机制测试中定位问题，再另建未见世界观和人工标注集评估。当前结论是：格式失败在本次样本中未复现，证据门仍有效但系统同时有漏报与误报，不能宣称开放场景质量达标。

## 复现与解释

运行器需要已有数据库中的账户级 Provider 快照，`--source-run-id` 仅引用一个本地分析运行；不在仓库配置或命令行传入密钥。执行 `--split dev` 或 `--split holdout` 会产生真实模型调用和费用。`--max-total-tokens` 是保守总账上限。运行器在标准输出给出脱敏 JSON，在标准错误给出每例进度；终态错误只报告异常类型，不报告可能含请求/响应内容的异常正文。

本次没有保存逐例原始模型回复，也没有把这 18 例包装成正式准确率。后续若需要可重复审计，应在**新**冻结夹具上保存脱敏逐例产物、运行配置指纹与代码包哈希，并保证原始产物只创建不覆盖。
