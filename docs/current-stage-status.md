## 这轮改动与作者操作

- **解释角色行为时区分两种方向。** “两周内不吃”是一项负向限制。如果原文确实要求禁食，原文就支持这项限制。模型现在会分别核对说法的方向、原文是否支持，以及期限能否支持长期设定。诊断可记录校验失败所在的冻结文档行和分句、初次与纠正的判定类别，不保存模型回复全文。本次医嘱例没有重现旧故障，旧记录也无法追溯到具体是哪句被拒收。
- **部分审查完成后可以补查。** 服务恢复后，去“文稿校验”选择同一批章节，再勾选“角色深度审查”并开始。无需改正文，新报告使用当时的文稿与基线，旧报告仍保留。已用隔离测试账户走过实际接口和工作进程，在测试中让模型服务返回 503 再恢复。新审查默认关闭深度审查。[作者操作步骤](local-pro-gateway.md#用已确认的角色设定审查一章新稿)
- **报告区分处理进度和实际判断。** 网页与 Markdown 按角色设定分别统计发现冲突、未发现冲突、未找到可比较行为、证据不足或待确认、未处理。正式问题数与设定项数独立，网页另列待复核线索。[报告功能验收](https://github.com/print636/LoreGuard/actions/runs/41796380489) · [本轮功能验收](https://github.com/print636/LoreGuard/actions/runs/41799525486)

## 下一步按什么顺序做

1. **优先弄清有行为却无法比较的原因。** 歧义发言的两轮输入和目标设定相同。上轮补充查找时从新稿第 3 行取到发言；这次没有取到。现有记录无法确认这次是否尝试过第 3 行。下一步先区分系统漏选原文、模型没有提出行为、提出的行为未通过证据核验这三种情况，再决定如何改进。语气有歧义时，有原文依据的待复核线索仍是合适结果。
2. **定位报销例未完整处理的那段材料。** 区分原文缺少有效证据和抽取过程出错，再决定是修抽取或改进恢复。保留检查范围不足时只能展示线索的门槛。
3. **用未参与开发的新故事验证。** 在查看结果前固定输入、判断规则与评分方式，分别报告可评估比例、正式判断和线索的证据质量。待普通稿件的覆盖稳定后安排真实作者试用，再决定是否做持续公开托管。[部署准备](production-deployment.md)
