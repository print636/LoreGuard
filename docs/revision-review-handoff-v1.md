# 修订后连续核对 V1

状态：实现与本地集中验收已完成，尚待 CI 和本机交付。2026-11-11。

## 解决的操作断点

作者已经可以把改名或跨格式的文件明确保存为原文稿的新版本，但保存后阅读正文、查看改动、确认资料身份和返回复检分散在不同位置。本阶段在既有报告修订路径中接通这些操作，沿用已有原文预览、文本差异和身份编辑能力，不另建文本比较算法。

## 连续操作

1. 作者从原报告进入修订，明确选择原文稿并上传文件。
2. 已核对成功响应后进入“核对新版本”，展示本次保存版本的正文及它与明确替换目标的改动。
3. 在同一步核对这份新版本的当前资料身份和故事范围，作者主动保存确认；不自动继承确认、发布或撤销角色特征。
4. 返回原报告的复检准备，重新核对当前选入资料及身份。只有作者另行点击开始复检才创建分析或使用模型。

正文差异的旧侧取本次明确替换的版本，复检基准仍是原报告。例如报告保存 v1，上传前选中 v3，保存为 v4：正文比较为 v3→v4，复检仍以原报告为基准。不能把这两种“旧版本”混为一谈。

## 版本与恢复

- 正文、差异和身份编辑固定指向所选文稿 ID 与版本，按当前账户及项目校验；不使用同名最新文稿替换。
- 路由可保留查看目标，但不是上传成功的证据。刷新或直接打开链接时重新核对实际文稿，不声称恢复了原文件、上传收据或可重试操作。
- 若刚保存的版本已被更新版本替代，仍可查看该历史版本及其与原目标的改动；本连续核对步骤停止身份写入及继续复检，提示作者明确选择并核对当前稿，不能看着 v2 却无感复检 v3。
- 上述是本前端旅程的保护规则，不改变后端人工身份修订允许编辑历史版本的既有合同。
- 编辑中的字段沿用现有离开保护与账户／项目隔离，不增加浏览器持久存储或自动保存。
- 返回准备与实际提交复用既有资料选择，并补齐客户端预期输入与提交时选材的一致性检查。现有服务端去重签名不能代替该检查；期间资料变化必须重新核对，不以曾经核对过某版本代替提交时检查。
- 所展示身份是该文稿当前身份；旧报告冻结的身份与正文仍由原报告读取，不被本步骤改写。

## 比较范围说明

复用服务端返回的逐行差异、比较限制和截断标记。没有差异块且比较输入完整时，才可说明比较未发现正文改动。输入被截断时，只能说明已比较范围内未发现差异，未覆盖部分不能确认；输出被截断时说明展示不完整。两种限制分别说明，不把局部无差异写成全文相同。

这里比较平台保存的解析后正文，不比较 Word 排版、批注、修订痕迹，也不判断改动是否修复了剧情问题。

## 复检预期输入接口

资料变化响应的 `recheck.input_signature` 提供可核对当前选材的签名，不可核对时为 null。前端从最新准备结果取得它，提交 `expected_input_signature`；没有可核对结果时先重新读取，不绕过连续核对。

服务端在现有项目写入锁内，按同一基准报告重新选择资料，比较预期签名与当前签名。签名绑定项目、基准报告、精确文稿选择及正文／版本／身份／范围／已确认档案；不一致时在创建分析和调用 Provider 前返回 `409 recheck_inputs_changed`，作者重新核对后再自行提交。

提交结果因网络中断而未知时，页面保留同一操作标识、请求内容、预期输入和深度审查选择，作者可以安全重试；不把另一组资料当成同一次操作。成功操作的原标识重放仍返回原结果；同一标识带不同预期输入不得冒充原操作。未传预期字段的旧客户端沿原合同处理。使用现有运行字段记录预期信息，不新增数据库列或迁移。

## 工程范围与验收

复用现有 preview、diff、narrative-context 和 material-impact 接口，按核对结果为复检提交补齐最小预期输入校验。该校验保留未传预期字段的既有调用兼容，不需要数据库迁移、模型调用或新分析；不接自然语言查询、外部插件、全书状态库或自动复检。

一次集中验收覆盖保存后的真实连续旅程、原报告 v1／替换目标 v2／新稿 v3 的区分、同版本身份、未保存保护、失效版本不切换最新稿、截断差异说明及必要窄屏显示。修复集中发现的问题后只复查受影响部分，再运行必需 CI。具体记录见[验收清单](revision-review-handoff-acceptance-v1.md)。

这是作者操作与版本可追溯性的改进，不是新的模型准确率或人工评测成绩。
