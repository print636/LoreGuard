# 报告逐证据来源与冻结资料导出验收 V1

状态：唯一合并集中验收已完成，无生产阻断；官方 CI 与发布待 root 文档合并后进行。

## 本批作者任务与边界

作者下载一份已完成审查的 Markdown 后，应能逐条辨认正式问题依据的文稿、版本、原文行区间和核验限制。当前资料被修改、同名文稿存在或依据来自此前确认特征时，不能把当前版本冒作旧报告出处。

沿用 `GET /api/v1/analysis-runs/{run_id}/export.md`、原正式问题、反馈和开放问题范围。不新增故事分析、模型请求、候选确认或复检；不以“已核对原文”宣称判断一定正确。完整来源、仅已存摘录可核、缺失、不一致与不可访问的准确文案，以最终服务合同为准。

用户已选择 Word/Markdown 文件工作流。本批同时验收所选报告的冻结资料 ZIP：作者默认未选文稿，只能勾选该报告的显式输入，通过 `GET /api/v1/analysis-runs/{run_id}/source-materials.zip?document_id=…` 下载。统一包内含目录 Markdown 和所选原样正文 Markdown；正文不得加元数据前缀。最多 100 份、UTF-8 正文合计 20 MiB，缺失或损坏来源整包报错，不静默漏掉文稿。

Word 作者继续编辑原 Word 并同名上传；Markdown 恢复原名上传。ZIP 是阅读/参考的冻结资料，不代表生成可无损往返的 Word，也不放宽原版本归属或自动发起复检。

## 合并 ZIP 的单次集中旅程

1. 在救生衣旧报告中读下载说明，确认文稿默认未选、不能空选下载；仅勾选一份显式输入。
2. 实际下载 ZIP，核目录可读名称/冻结版本/角色与范围说明；按冻结全文摘要和字节核对正文 v1，无新增 metadata 前缀。未选文稿无正文文件，隐含的确认来源不自动混入选材。当前 v2 不替代旧 v1。
3. 选中状态下验证失败保留选择、切报告清空；会话失效和旧请求迟到不下载错误报告。采用少量精确网络夹具验证交互，不改真实资料制造损坏，也不把 mock 边界称为真实报告成绩。
4. 在真实 QA 后端连接下保存桌面/375 像素的同一下载区与说明截图，核操作可见且无横向溢出。导出、关闭和切换均不触发分析请求。

坏源、上限、损坏身份以及“旧时确未保存身份”与“已存身份损坏”的区别，复用新增后端专项，不重新造多份语料或重跑原 40 项报告来源用例。请求内 reader 缓存仅可复用本次同报告授权来源；每条行区间、摘录仍须独立核验，不跨请求/报告/用户沿用缓存。
