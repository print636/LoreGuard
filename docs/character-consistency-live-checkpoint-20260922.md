## 本轮暴露并修复的问题

此前真实运行显示，多目标合并查漏会让一个目标的空结果掩盖另一个目标，同时单次运行预算可能在角色阶段前被主抽取消耗。当前实现将单次运行默认预算提高到 100,000，同时保留角色阶段 60,000 的独立上限；查漏改为按目标分别调用。

若某个目标首次查漏返回结构合法的空结果、但仍未达到下游证据门槛，系统至多再进行一次候选行核验。核验只展示未排除且完整点名该角色的原文行，并保留原始全局行号；模型输出仍绑定完整冻结原稿，证据范围还必须精确命中服务端候选行白名单。规则不会生成角色信号，两次均为空就保持为空；预算不足、取消、非法输出或 Provider 失败都会明确降级为不完整覆盖。

## 边界

这是开发者可见原创样例上的工程验收，不是人工盲测、冻结 holdout、开放文本泛化成绩或生产质量证明。三次通过只证明当前构建在这组已知用例上能够稳定走完权威资料确认、证据抽取、模型复核和问题展示闭环，不能据此外推到任意长篇剧情。

复现时应使用服务端环境变量配置模型，并让运行 artifact 留在 Git 忽略目录：

```powershell
python scripts/run_character_consistency_live.py `
  --base-url http://127.0.0.1:8000 `
  --trials 3 `
  --run-timeout-seconds 1800 `
  --output-json artifacts/character-consistency-live.json
```

Runner 不读取或输出 Provider 凭据、服务地址、Prompt、原始响应或故事正文；提交前仍应单独检查本地 artifact 与 `.env` 没有进入 Git。

## 提交前的安全与稳定性收紧

v26 已包含候选确认边界收紧：待确认档案必须继续匹配来源运行冻结的文档版本、内容哈希和叙事上下文；同一文档的权威、发布状态或分支发生变化后，旧候选会变为 `stale` 并拒绝确认。

模型给出的 `observation_kind` 不再直接决定证据强度。服务端会在逐字证据绑定后保守校准：直接喜恶表达可归为偏好表达，普通拿取或拒绝行为不会被升级；一次具体话术不能伪装成稳定特征声明。查漏阶段也明确区分“抽取发生过的行为”和“下游判断它是否有合理解释”，因此伪装、任务或成长原因不会让模型在抽取阶段漏掉可定位行为。主抽取与查漏仍不生成规则结论，最终问题必须经过冻结基线、独立证据门槛和受限模型复核。

本文件只记录上述明确构建的开发检查点；后续任何代码变更都不能自动继承这组 3/3 结论，必须重新生成 runtime provenance 并重复门槛。
