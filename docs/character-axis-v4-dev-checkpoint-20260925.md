## 决策与下一步

1. 保持 V4 默认关闭，不运行 TRANSFER，不改动冻结的选择器或 Oracle 来“修分”。
2. 先单独修复默认路径中已复现的直接偏好句完整宾语与方向误判，并通过正反例和全量回归；这属于既有产品正确性问题，不回填或篡改本次 V4 对照。
3. 先为 V4 增加默认关闭、无正文的逐断言诊断：只记录匿名断言序号、是否被模型提交、固定拒收原因及是否形成候选，区分模型漏抽与服务器拒收。任何后续能力改动都需要明确的句间关系证据或作者确认，不能仅按“同一行”跨分句继承主语或核心/稳定标签；尤其要反测他人、转述、问句、否定/转折和混合列表。单变量改动后再做真实模型 DEV 复测。只有 DEV 的基线、候选、新稿及五案评分稳定跑通，才按原先固定协议测试 TRANSFER。

这是开发者可见的小样本诊断，**不是盲测、开放文本泛化或生产质量证明**。项目已经可供演示与学习，但这项复杂角色轴能力目前仍未达到可对外承诺准确性的程度。
