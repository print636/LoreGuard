# 角色候选精确证据绑定 v1

此功能随 `character_signal_scope_review_v1` 使用，默认关闭；该开关依赖 V5 语义作用域与 V4 断言索引。仅通过复核的正式角色设定进入这条新路径。历史剧情归纳、草稿和开关关闭时的候选仍沿用原流程。

新路径中，一个目标 `support_id` 对应一条待作者审核的主张。同一原文行若含两个获支持的目标分句，会生成两条候选；确认其中一条不会确认另一条。角色、标签锚点及两者到目标之间的分句只标为承接上下文，不能替代目标子句。候选仍保存并展示完整原文行，但精确目标和上下文位置由服务端从分析运行的冻结文档重新分句并计算 Unicode 码点偏移，不采信模型提供的坐标或额外 `basis_ids`。

候选的 `formal_target_v1` 指纹在原语义组和整行证据基础上绑定项目、冻结文档 ID/版本/内容哈希、目标 ID、角色与标签锚点、承接关系及断言索引版本。不同目标或证明链不会静默合并；同一冻结目标在不同运行中出现忠实的自然语言改述，仍可复用既有候选。原有候选指纹、整行 `evidence`、作者确认快照协议和旧冻结 DEV 评测 gate 不变。旧 gate 仍可能因要求候选表述包含原文短语而漏收合理改述，精确位置不被用来偷换该门槛。

迁移 `0016` 增加候选来源标记、绑定 JSON 和校验哈希：迁移时将此前的候选标为 `legacy_v1`，新流程生成的精确绑定候选标为 `required_v1`，关闭新流程后新增的旧式候选也显式标为 `legacy_v1`。三列全为 `NULL` 不再代表旧候选，而是损坏状态。授权候选 API 对新行再次核对冻结输入、分句坐标、绑定哈希和候选指纹；缺失、损坏或被同线另一合法目标/锚点替换时返回 `support_bindings_status=invalid`、`reviewable=false`，确认及旧偏好替代关联接口返回 409。幂等确认回放也先判定来源类型、验证新行冻结绑定；跨运行去重若命中损坏的新行则记为部分失败，不把它计作成功复用。真正的 `legacy_v1` 行保持原有审核与回放行为。

PostgreSQL 迁移及全新建表包含来源标记与绑定的组合约束，并拒绝空标记。SQLite 已有库的迁移物理上只加可空列并回填旧行标记：在临时库测试中，重建候选表会丢失既有约束，因此没有用表重建强加新 CHECK；SQLite 升级库依赖写入验证和 API 的 fail-closed 检查。`0016` 降级时若有 `required_v1` 或任何非干净 `legacy_v1` 行会拒绝执行，以免删除绑定列后把新候选伪装成旧候选；空库或只有干净旧候选仍可降级。这里的结构化绑定只解决来源定位和审核粒度，不证明模型在真实长篇故事上的语义准确率。
