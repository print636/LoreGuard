# 无正式设定首审：开发检查点（2026-09-27）

本文只记录项目内“仅新稿自检”的入口、范围保护和小样本诊断；不能据此推断开放文本准确率、长篇生产质量或角色 OOC 能力。测试文本均为本轮原创、开发者可见，并且为了定位问题刻意调整过写法；不是独立盲测集。真实模型使用本地 OpenAI-compatible 配置的 `deepseek-v4-pro` 别名，别名不证明上游实际权重；不保存或公开 API Key。

## 已实现的范围合同

- 无在用正式设定/已发布历史时，可在项目“文稿校验”中选择已人工确认的草稿/审阅中章节，发送带显式 target ID 的 `draft_review`；不必编造世界观，也不会把其他草稿升格为背景。
- 客户端提交前复核目标版本和资料身份；服务端在创建运行的项目锁内对 `no_formal_context_expected=true` 再次核对。活动中的正式设定/角色资料（仅已确认退役者例外）或已发布历史章节即使尚未人工确认，也会返回 `409 formal_context_present`，不静默扩大或缩小本次范围。该意图进入冻结摘要、幂等比较和复检；已有资料出现时，复检也拒绝悄悄变成另一类审查。
- 该原子性覆盖通过 API 创建/替换文档、人工确认或模型推断回写上下文、启动审查与复检：PostgreSQL 使用项目行锁；本地 SQLite 在首个读取前显式开启 `BEGIN IMMEDIATE`，以全库写锁串行化这些写入。已用双向并发交错测试验证“先上传再审查→拒绝”“先冻结再上传→本次范围不变”。SQLite 因此只适合本地/轻量使用；其他写请求可能等待，外部脚本绕过 API 改库不在保证范围内。
- 作者已确认的角色特征可在来源资料退役后继续生效。因此“无在用正式文档”不等于“没有角色基线”；没有适用的已确认特征时，角色 OOC 必须弃权。前端与报告页明确提示此边界，问题列表称为“线索”而非作者已确认结论。
- 同时刻多地点规则新增严格可核的中文完整绝对时间 `YYYY 年 M 月 D 日 HH:MM[:SS]`：必须为有效日期、完整出现在事件证据中，且不能带“约、左右、或”等近邻不确定语气。只有时分、相对日期或无效日期仍不产生确定冲突。地点层级抑制不再因共享“灯塔”等短词就认定同址；保留明确“议会的密室”“月沫城的中央档案厅”等从属关系保护。自然文本解析还补上“查阅”动作边界，避免把“查阅卷宗”吞进地点名。原文证据和历史运行不改写。

## 隔离 HTTP + 真实模型诊断

使用本地隔离 SQLite 项目、`USE_CELERY=false`、`ENABLE_MODEL_EXTRACTION=true`、`ENABLE_CHARACTER_CONSISTENCY=true`。以下每次都只选 1 个已确认草稿，冻结背景数均为 0，任务均完成并实际使用模型；“任务完成”不等于模型全覆盖。前 3 次在规则修补前，后 3 次在规则修补后；模型响应也不保证逐次相同。

| 输入与阶段 | 模型抽取 | 可见地点冲突 | 已观察到的限制 |
|---|---|---:|---|
| 含相互矛盾但明确写为“待核实记录”的叙事，修补前 | 部分降级 | 0 | 3 条词面证据拒收；仅 `HH:MM` 及待核实语气不足以确定同刻冲突 |
| 完整中文年月日时分、东西灯塔及钥匙，修补前 | 部分降级 | 0 | 4 条字段类型拒收；两条事件已接纳，但中文时间与短地点词保护分别阻断规则 |
| 等价的 ISO 时间、独立西塔/东港地点，修补前 | 完整模型增强 | 1 | 第 3、5 行双证据；仅验证明确输入可走通模型→规则→问题链路 |
| 完整中文年月日时分、独立西塔/东港地点，修补后 | 部分降级 | 1 | 第 3、5 行双证据；仍有 1 条词面证据拒收 |
| 原“东西灯塔及钥匙”草稿再次运行，修补后 | 部分降级 | 1 | 第 3、5 行双证据；仍有 1 条词面证据拒收、2 条字段类型拒收 |
| 同一草稿在“查阅”地点解析边界修补后再次运行 | 部分降级 | 1 | 第 3、5 行双证据；仍有 4 条字段类型拒收；此轮没有声称模型全覆盖 |

上述不是“六例准确率”：样本与规则在测试中改变，样本过少、非盲测，也未标注全部可能问题。所有这些运行的角色阶段均为 `partial`，项目没有已确认角色特征，**0 个角色 OOC 案例得到质量评估**。后续需独立冻结新故事与标注，再分别评候选覆盖、证据命中、误报和漏报；模型字段类型拒收与复杂角色归属仍是待诊断项。

## 工程回归边界
