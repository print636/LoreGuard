# 故事工作台与常用审查改进

日期：2026-11-07。状态：阶段 0 接收与拆分完成，阶段 1 前端和引擎并行实施中。起点为 dce965a；已有交付及质量结果保留。

本阶段交付一套可实际体验的故事资料与审查工作台，并处理限定范围的常用审查缺口。外部工具仍承担主要写作，LoreGuard 负责导入、资料维护、阅读、审查与修订追踪。

## 范围与复用

| 工作包 | 复用 | 本阶段调整 |
| --- | --- | --- |
| 平台入口与作品列表 | 公开入口、访客空工作区、个人项目、导入和账户 | 分清平台入口与作品内部操作；真实作品和继续操作入口更容易找到 |
| 作品资料与阅读 | 资料库、原文、版本、角色候选和确认 | 章节／资料目录、常驻正文、任务辅助面板形成连续工作区；合理折叠并保留阅读上下文 |
| 审查设置和任务 | 已有输入选择、模型配置、任务、进度、取消重试 | 目标与依据分别呈现；检查选项及恢复路径可发现，后台进度不伪造倒计时 |
| 报告与复检 | 正式问题、线索、冻结证据、反馈、导出、修订、比较、发布 | 问题与双方依据联动；下一步处理与返回原文更顺畅，真实未决状态不隐藏 |
| 账户及状态体验 | 当前登录提醒、模型设置、草稿恢复合同 | 设置入口与空／加载／失败／过期说明整合，不另建供应商、缓存或认证体系 |
| 常用审查质量 | 既有目标绑定、行为核实、情境及解释复核 | 核实普通适用情境与同句多角色归属的共同缺口，仅据实际原因修复 |

前端不等待语义质量全面通过。已有响应合同足以表达部分覆盖、待复核和失败；如需新增字段，先确定合同及兼容，再接入。

## 设计起点

平台首页借鉴创作空间的层次感，固定导航组织作品与功能入口；单作品工作区以章节／资料目录、原文阅读、问题及依据三部分开始设计。保持温和的二次元元素和彩色“开始校验”主操作，长文阅读降低装饰干扰。

三个关键样稿为平台入口、作品资料阅读、报告审阅。样稿和导航映射先落地，再实施；精确尺寸、字体及窄屏折叠由前端决定。不得用假统计、固定模型结论、无作用按钮填充设计。

详细布局和接口映射由[前端方案](story-workbench-layout-v1.md)维护，阶段完成前需提供真实浏览器截图。

## 工作分工与依赖

| 角色 | 工作范围 | 依赖及交接 |
| --- | --- | --- |
| 开发指挥 | 范围、任务、合同协调、阶段记录和产品对齐 | 接收新需求；对真正改变产品语义的决定提问 |
| 平台与前端长期执行者 | 布局方案、既有组件整合、前端实现及必要组件验证 | 复用当前接口独立推进；需要后端变化时先同步，避免接口与引擎互相等待 |
| 引擎长期执行者 | 旧真实证据归因、共性补丁和相关核心验证 | 不预设一定修改代码；确认程序问题与模型不确定性，保留旧策略和失败 |
| 作者体验与验收长期执行者 | 用户任务清单、设计体验建议、稳定版本的一次集中审查和真实批 | 准备可先做；实现稳定后集中执行，不对中间版反复全站审查 |

前端、引擎分别拥有其生产代码及对应专项。验收角色维护阶段浏览器验收与模型批次，指挥维护阶段状态文档；共享文件或响应合同变更先协调。

## 首批验收

1. 访客可看信息页和空工作区，受保护操作才提醒登录，登录成功不自动重放操作。
2. 普通账户可导入只有正文的 DOCX 或 TXT，查看解析与资料用途；不要求预填完整世界观。
3. 设定及历史作为依据，新稿作为目标；版本、范围与模型可核对，深审默认关闭、图表可选。
4. 目录、正文、所选问题和双方冻结依据联动；切换不丢失关键阅读上下文。
5. 正式问题、线索、未覆盖与失败分别表达；正式问题反馈与导出保持原合同。
6. 修改后上传、复检、比较和手动发布可接续；旧报告读旧原文，未再检出不自动等于已解决。
7. 已有进度恢复、取消重试和已批准范围的防丢稿不回退；窄屏仍能触达主要操作。
8. 常见明确冲突、合理例外／范围排除、不确定结果分别留证；同句多角色归属不能借用他人动作。

首批真实材料以既有普通开发稿为主，在实现稳定后固定模型、输入和代码；具体批次由引擎诊断与验收准备共同确定。真实模型与工程测试分开报告，原十八题不再作为新的独立盲测。

## 验证节奏

集中开发期间只做必要的影响范围验证。稳定后一次集中作者体验审查，合并修复，再补受影响路径及必要 CI。只有明确修复或新问题才安排相应模型回归；成功、失败与未决均保留，不反复采样挑选结果。

权限、版本和证据来源的关键边界不能因减少审查而省略。前端关键页与代表状态有实际浏览器检查，不以静态样稿代替交付。

## 停止线及后续

本阶段结束于可体验的新工作台和限定范围的普通审查改进交付，同时明确仍未解决的质量问题。到该节点向用户进行一次产品对齐，不无限追加特定文风或罕见故事。

后续按产品对齐结果依次考虑：重新导入与资料变化影响、按收益增加一类故事状态／有出处查询、明确接入方后的外部 AI 协议。这些不在本阶段启动。

继续保留确认特征独立生效、作者手动发布、合理推断须有出处、BYOK、旧报告冻结和角色深审默认关闭等规则。团队协作、自动写作、质量评分、模型训练、商业游戏接入和高并发公网承诺不在本次范围。

## 分线计划估算

前端实现、组件与构建27–37小时；引擎7–14小时；统一作者验收与交付10–16小时。合计44–67小时工作量，前端与引擎并行，验收准备提前进行；去除重复验收后，关键路径及环境预留暂按40–60小时。这是条件估算，随实际发现调整，不是固定完成日期。

引擎已确认教学／课堂旧稿有动作选择，但独立核实以比较轴不同或中性拒绝，后续适用情境说明又受用途词与固定动作入口限制。本阶段批准替换原有最多一次情境说明调用，使用有界来源核对动作和适用关系；不将旧拒绝动作直接认证，不清除原记录缺口，不把单片段说明当全文审查完整。旧重试保留旧合同，公共报告字段不变。旧两人同句异常仍缺当时安全栈，不能预设根因。
