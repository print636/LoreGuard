# 真实模型稳定性与误差记录

更新时间：2026-09-02

## 评测边界

- Provider：本地 `.env` 中配置的 OpenAI-compatible 服务，模型名不写入公开报告之外的源码。
- 场景：`data/advanced/` 固定三文档开发回归场景，预期为五条问题、五种类别。
- 预期答案只在模型调用完成后用于评分，不进入 Prompt；报告不保存 API Key 或原始响应正文。
- 该场景已被开发者查看，样本数量很小，因此只能衡量同一场景的重复稳定性，不能代表开放文本泛化能力。

## 第一次重复运行（3 次）

| 指标 | 结果 |
|---|---:|
| 模型实际参与率 | 3/3 |
| 总 Token | 11,846 |
| 端到端 P50 / P95 | 35.51 s / 53.11 s |
| 首个进度事件 P95 | 3.36 ms |
| TP / FP / FN | 14 / 11 / 1 |

主要问题不是漏掉问题类别，而是同一类别出现重复或证据不可靠的额外问题。仅统计“类别是否出现”会掩盖这些误报，因此稳定性脚本已改为按类别与证据对进行精确问题评分。

## 第二轮修复当时的未验证状态

第二轮规则修复当时已经加入：同一证据不和自身冲突；共享明确地点词的嵌套地点不直接判为异地；知识越权必须存在可比较的显式知识获得记录。截至该阶段只通过了本地自动化测试，因此当时没有宣称真实 Precision 已经提升。

这段 0.556 Precision 是 2026-09-01 的历史结果，不能再作为当前成绩。它保留用于展示误报如何驱动通用协议修复，而不是覆盖或删除失败记录。

## 复杂原创 pilot 尝试（2026-09-01）

已建立 6 例预算化 pilot：一个五类跨文档正例，加上每类各一个困难反例，Token 硬上限为 25,000。此次中转 Provider 对 25 个分块请求全部返回安全封装的 HTTP 403，模型成功案例为 0、Provider 报告 Token 为 0，因此没有生成或宣称任何模型精确率。产品主链路均安全降级为本地基线，但这些结果被评测器排除在模型指标之外。

评测器随后加入系统性失败 fail-fast：若首个案例的 Provider 请求全部失败且没有任何模型分块成功，立即停止后续案例。当时结论是先恢复 Key、账户和模型权限，无需修改规则或 Prompt 来处理 403；权限随后已恢复。

## complex-v3 完整三轮复测（2026-09-02）

Provider 权限恢复后，先完成 6 例 pilot × 3 轮：18/18 完整无降级、75/75 次调用成功，严格类别和完整证据均无 FP/FN。随后对完整 14 例执行 3 轮正式复测：

正式报告未把预期答案放入 Provider 输入，也不保存 Prompt、响应正文、Key 或 endpoint。当前结论是“模型增强固定回归门槛已通过”，不是“开放文本达到 100%”：complex-v3 由开发者编写且可见，修复也参考过它的上一轮错误。下一阶段准确率工作的价值在于独立世界观人工盲标集，而不是继续针对这 14 例调参。

## 2000 字延迟门槛（2026-09-02）

将原创生成型长文截取为一个固定 2000 字单文档，真实模型重复 5 次。5/5 次均有模型参与，无意外问题；首进度 P50 0.10 ms、P95 5.91 ms，端到端 P50 6.30 秒、P95 7.94 秒，总计 11,799 Token。它只测单文档短文本主链路延迟，不含准确率标注，也不能替代并发压测或生产 SLA。
