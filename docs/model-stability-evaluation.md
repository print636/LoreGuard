# 真实模型稳定性与误差记录

更新时间：2026-09-01

## 评测边界

- Provider：本地 `.env` 中配置的 OpenAI-compatible 服务，模型名不写入公开报告之外的源码。
- 场景：`data/advanced/` 固定三文档开发回归场景，预期为五条问题、五种类别。
- 预期答案只在模型调用完成后用于评分，不进入 Prompt；报告不保存 API Key 或原始响应正文。
- 该场景已被开发者查看，样本数量很小，因此只能衡量同一场景的重复稳定性，不能代表开放文本泛化能力。

## 第一次重复运行（3 次）

报告：`artifacts/model-stability-advanced.json`

| 指标 | 结果 |
|---|---:|
| 模型实际参与率 | 3/3 |
| 总 Token | 11,846 |
| 端到端 P50 / P95 | 35.51 s / 53.11 s |
| 首个进度事件 P95 | 3.36 ms |
| TP / FP / FN | 14 / 11 / 1 |
| Precision / Recall / F1 | 0.560 / 0.933 / 0.700 |
| 完全正确运行率 | 0/3 |

主要问题不是漏掉问题类别，而是同一类别出现重复或证据不可靠的额外问题。仅统计“类别是否出现”会掩盖这些误报，因此稳定性脚本已改为按类别与证据对进行精确问题评分。

## 第一轮通用证据约束后（2 次）

报告：`artifacts/model-stability-advanced-post-guards.json`

| 指标 | 结果 |
|---|---:|
| 模型实际参与率 | 2/2 |
| 总 Token | 8,135 |
| 端到端 P50 / P95 | 63.62 s / 92.92 s |
| 首个进度事件 P95 | 3.75 ms |
| TP / FP / FN | 10 / 8 / 0 |
| Precision / Recall / F1 | 0.556 / 1.000 / 0.714 |
| 完全正确运行率 | 0/2 |

五类目标问题在两次运行中都出现，但每次仍有 4 个额外问题，集中在嵌套地点被误判为同刻异地，以及没有明确知识获得记录时把角色陈述判为知识越权。

## 当前修复及尚未验证项

第二轮规则修复已经加入：同一证据不和自身冲突；共享明确地点词的嵌套地点不直接判为异地；知识越权必须存在可比较的显式知识获得记录。全部本地自动化测试通过，但尚未再次消耗真实模型 Token 重跑，因此不能宣称真实 Precision 已经提升。

结论：真实 Provider 主链路可用，失败降级、预算和耗时记录也已接通；但固定场景真实模型 Precision 目前只有约 56%，尚未达到计划中的 75% 投递门槛。下一次模型付费评测应在新增独立复杂场景和人工标注后进行，避免继续针对同一个已知场景调参。

## 复杂原创 pilot 尝试（2026-09-01）

已建立 6 例预算化 pilot：一个五类跨文档正例，加上每类各一个困难反例，Token 硬上限为 25,000。此次中转 Provider 对 25 个分块请求全部返回安全封装的 HTTP 403，模型成功案例为 0、Provider 报告 Token 为 0，因此没有生成或宣称任何模型精确率。产品主链路均安全降级为本地基线，但这些结果被评测器排除在模型指标之外。

评测器随后加入系统性失败 fail-fast：若首个案例的 Provider 请求全部失败且没有任何模型分块成功，立即停止后续案例。下一次复测前应先确认 Key 有效、账户余额和 `deepseek-v4-pro` 模型权限；无需继续修改规则或 Prompt 来处理这次 403。
