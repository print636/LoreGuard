# 角色 OOC 跨剧情开发检查点（2026-09-23）

本检查点使用新增的原创 [潮镜站 DEV 挑战集](../data/character-ooc-challenge-v1/README.md)，经本地 HTTP API、PostgreSQL/Celery 和账户级 OpenAI-compatible Provider 跑完整角色设定候选确认与新稿审查流程。请求配置中的模型别名是 `deepseek-v4-pro`；别名不证明上游实际权重。样本由开发者编写并在本轮调试中可见，**不是盲测、开放文本质量或生产可用性结论**。

## 预先关注的三种情况

1. 南枝：在两个独立时段主动与陌生人长谈，正式核心性格与新稿相反，材料中没有已发生的成长或任务桥梁；期望带基线和两条新稿证据的冲突。
2. 郁礼：同样出现更主动的公开交流，但已发布章节记录连续八周训练；不能报确定冲突，只有在观察和因果证据都被抽取、绑定后才能说明“已解释”。
3. 岑烛：警报发生时仅一次厉声打断队友，随后恢复平时方式；不能据单次紧急行为判定稳定人格改变。

Oracle 只在模型输出后用于评分，不进入上传正文、模型 Prompt 或账户配置。首次 DEV 探针暴露了岑烛标注的比较轴方向歧义；现以 `interruption_restraint/positive` 或 `interruption_behavior/negative` **成对**接受，不接受交叉组合。该修正发生在开发集观察之后，所以本集从未具有 holdout 资格。

## 判断边界与后续定位
