# 项目名称与说明编辑 V1

项目中心每个项目旁的“编辑信息”，以及工作台当前项目旁的“编辑项目信息”，允许修改故事名称与说明。不会改变正文、资料身份、发布状态、角色特征、选中运行或既有报告。

## 编辑与保存

打开表单时才请求 `GET /api/v1/projects/{project_id}/metadata`，核对项目 ID 和 `metadata_revision`。读取失败提供重试，不从项目目录中的旧摘要猜测修订号。名称去掉首尾空白后不能为空，最多 200 个字符；说明沿用已有字符串约束，不新增截断。

保存请求为 `PATCH /api/v1/projects/{project_id}/metadata`，只包含 `name`、`description`、`expected_revision`。服务端按工作区隔离并执行乐观并发检查；同一版本没有实际变化时不增加修订号。成功后重新读取当前有界目录，保持搜索和排序，并更新工作台项目标题，不重新读取或清空正文、导入队列、反馈或分析运行。

输入仅在内存中；未保存时关闭、Esc、取消、页面内导航或刷新有离开确认，不写入浏览器存储。表单在读取前不可编辑；保存期间防止重复提交。请求失败保留输入；项目或账户改变、表单关闭后，迟到响应不能更新新项目的标题或新表单。

## 并发冲突不自动覆盖

如果别的页面先修改了项目信息，旧 `expected_revision` 得到 409。表单保留作者填写的名称和说明，但阻止直接再次保存。作者点击“读取最新项目信息”后：

1. 服务器最新内容另行展示，不自动替换当前输入。
2. 可以选择“保留我的改动，合并最新内容”。以打开／上次保存时的基准判断哪些字段真正被作者改动：这些字段保留作者输入；未改动字段采用服务器最新值。页面明确提示哪些字段之后保存会替换。
3. 合并只调整本地表单与保存基准，**仍需作者检查后另行点击保存**；不会自动 PATCH。
4. 也可选择“采用最新内容”，放弃当前修改。存在未保存修改时需再次确认。

保存请求返回不完整或连接中断时，同样显示结果待核对。应显式读取最新版本后再决定，而不是声称保存肯定没有发生。成功保存但目录刷新失败另行提示，已保存内容不会回滚，也不要求重复保存。

## 可访问性与验证

沿用星轨书斋的色彩、字体与语义 tokens，普通保存动作不使用“开始校验”的彩虹样式。使用原生 dialog、可见字段标签、键盘焦点、Esc 恢复和原触发按钮焦点返回；错误与保存状态以文本和可访问状态区域呈现。375px 手机布局保持可读、可点击，不横向溢出。

Helper 单元测试核对身份、修订号、字段验证与显式合并；Mock 浏览器测试核对成功、失败保稿、并发恢复、键盘关闭和迟到响应。它们不代替真实后端租户权限、CSRF、迁移与并发测试，也不涉及模型调用或人工封闭评测内容。
