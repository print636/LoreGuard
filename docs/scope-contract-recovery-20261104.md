# 原文校验的有界纠正与拒因观测

日期：2026-11-04。本组针对上轮普通 DEV 中已经观察到的校验矛盾，不扩大故事场景，也不改变角色冲突的成立门槛。

## 原文校验的内部矛盾

scope 审查负责判断模型提取的记录是否忠于原文，与“角色是否 OOC”是两个步骤。上轮医疗材料的一项输出同时声称提议得到原文支持，又给出与该判断不兼容的极性关系，已有门禁正确地将其降为未确定；原实现没有针对这种内部矛盾的纠正机会。

现在只对本地能明确检查的 `supported` 与固定语义槽冲突重问一次，仍与格式／身份纠正共享“原调用加一次纠正”的两轮总上限。一般拒绝或不确定不会为了得到更有利结果反复询问。冻结请求、来源、提议、来源／basis／槽校验、总预算与 deadline 保持生效；纠正提示只列固定冲突字段，不指定模型必须回答 `same` 或支持。

混合批只更新首轮冲突项，其他合法判断保持不变。第二轮无效、超时或预算不足时保留首轮合法结果，未解决部分继续保守处理。初次冲突历史与恢复计数分别保留。

恢复成功表示返回了经过既有门禁的合法判断，可能是支持、拒绝或不确定，不等于资料完整。有效拒绝仍不产生事实候选；当前提取器对记录被拒后的覆盖缺口继续保留部分覆盖。

## 失败原因观测

内部诊断增加固定原因、枚举、计数、摘要和安全位置，区别陈述支持检查的不同环节，并记录定向语义拒绝的负向槽、请求方向及判定。接受和拒绝规则不变；不保存原提议、原文、任意模型解释、异常正文、URL、凭据或请求头。仅有实际数据时输出新诊断，不据历史汇总反推过去的模型理由。

恢复策略有固定版本。历史报告可按只读兼容路径解析；新的 live preflight 必须匹配当前版本，未知版本不得回落为旧模式。
