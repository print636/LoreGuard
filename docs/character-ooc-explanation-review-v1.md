# 角色 OOC 语义解释复核 V1

## 目的与启用方式

角色的反常行为不一定是设定冲突，也可能来自成长、恢复、伪装、身份扮演、临时状态、压力或伏笔。`CHARACTER_EXPLANATION_REVIEW_V1` 为角色漂移候选增加一条受限的 AI 解释复核路径：它只在本次运行已经冻结的授权材料中寻找解释候选，再让模型逐条判断候选与当前角色、比较轴、发生状态、时间和因果关系是否一致。

该能力是角色一致性阶段内部的实验门，默认关闭。隔离的本地开发环境可在未提交的 `.env` 中设置：

```dotenv
ENABLE_CHARACTER_CONSISTENCY=true
CHARACTER_EXPLANATION_REVIEW_V1=true
CHARACTER_EXPLANATION_TOKEN_BUDGET=24000
```

它还需要可用的聊天模型 Provider。开关、预算或 Provider 配置缺失时，不应把这条路径描述为已经运行；以运行诊断中的 `explanation_review_enabled` 与 `explanation_coverage` 为准。未启用时，存在角色漂移候选的个案保持 `not_run` 并只能进入待复核线索，整个角色阶段也不能显示完整覆盖。当前实现及模拟回归不代表真实模型开放文本准确率，也没有完成真实封闭 holdout 评测。

## 冻结候选发现，不是 embedding RAG

服务端先从本次运行的冻结快照构造小型证据窗口，再将候选交给模型。已确认的 `draft` 与 `in_review` 章节都按待审稿处理；已确认、沿用旧上下文且发布状态为 `unknown` 的正式角色档案仍按正式资料审查并保留原始状态。只要每个原文行不超过 16000 字符且候选仍在阶段上限内，系统会对适用来源做覆盖全部非空原文的确定性分段，因此不会因为角色只以别名、代词或跨句承接出现就把“没搜到名字”误当成解释搜索完成。超长单行会被拒绝并标为 `partial`；候选超限时只使用词面、语义轴、角色和局部性信号排序本轮窗口，也同时标为 `partial`。候选发现受来源、发布版本、分支、活动、行号、数量和 Token 预算限制；它不调用 embedding，不使用向量索引，也不应称为 embedding RAG。

模型不能自行搜索数据库、补写证据或扩展候选。每个候选都有服务端签发的 `E` 编号和精确的冻结文档、版本、行号、原文及来源元数据；响应必须逐项回显同一批编号。候选按最多 8 条一批复核，底层协议硬上限为 64 条，当前角色阶段每个 OOC 个案最多选择 24 个窗口；超过 24 个即使优先窗口完成复核也仍标为部分覆盖。所有批次共享一个每个案的解释复核预算上限，同时还受角色阶段与本次运行剩余额度以及最终裁决预留额度约束，这些额度不能相加理解为可用总量。

模型只返回受限枚举：解释类型、是否真实发生、是否同一角色、是否同一比较轴、是否在当前行为之前发生或仍有效，以及因果关系属于明示、有限推断、无关还是不确定；同时只能从本批冻结的 `C` 白名单中逐项声明候选实际适用的当前观察。服务端把这些位置句柄转换成稳定的观察 ID 后再生成支持证据，避免观察重排时错误重绑定。原文中的命令不受信；Prompt、模型原始响应、思维链和密钥不持久化。

## `B/C/G/X/P` 证据角色

最终角色复核使用服务端签发并映射回冻结原文的证据编号：

- `B`（baseline）：作者已确认且适用于当前稿件的角色基线。
- `C`（current）：待审新稿中的当前行为或陈述。
- `G`（growth / causal bridge）：能够解释变化的成长或恢复证据。
- `X`（exception）：伪装、身份扮演、临时状态或压力等适用例外。
- `P`（possible explanation）：伏笔、歧义、有限但不足的因果关系，或尚不能提升为 `G/X` 的解释线索。

`G/X/P` 不是模型仅凭类型标签就能生成的事实。所有支持都必须属于同一角色与同一轴、明确绑定适用 `C` 并通过冻结来源和服务端时序校验；`G/X` 及普通有限推断还必须已经真实发生且在当前行为之前发生或当时仍有效。伏笔类 `P` 可以是传闻、假设、未来或不确定状态，因为它只代表线索而不是已发生事实：

- 已发布的正式资料或历史只有在因果关系明示时才可以形成 `G/X`。当前协议没有能证明“独立事件且支持同一因果命题”的服务端身份，因此 `bounded_inference` 一律保留为 `P`；不同窗口或不同文档不能靠计票升级。
- 同一待审稿可以用**明示**的伪装、身份扮演、临时状态或压力解释本稿中的反常行为，因此可形成 `X`。
- 同一待审稿不能用“角色已经成长/恢复”来自证本稿的人格变化；这类草稿成长说明最多形成 `P`，不能成为 `G`。
- 伏笔、含糊暗示、传闻、假设、未来计划或因果不足的候选最多形成 `P`。普通成长、伪装或临时状态候选若明确无因果关系，不形成支持证据；但已绑定同一角色、同一轴和适用 `C` 且通过服务端时序门的伏笔或计划，即使不声称因果也可保留为 `P`。同稿中写在 `C` 之前的未来计划可作为线索，写在 `C` 之后的计划不能反向绑定更早的 `C`。
- 相同冻结证据不会因为被重复发现而算成两份独立支持。
- `G/X/P` 只作用于其服务端绑定的当前观察；`explained` 所引用的 `G/X` 绑定并集必须覆盖该裁决实际引用的全部 `C`。只解释 C02 的例外不能把同时引用 C01 与 C02 的裁决判为已解释；反过来，只绑定未被最终冲突裁决引用的线索也不会无关地否决另一组 C。

## 晋升与失败边界

正式角色冲突必须同时满足既有的双侧证据、事件独立性、材料覆盖和最终复核合同。解释复核在此基础上增加以下 fail-closed 边界：

- `P` 永远不能直接支持 `explained`，也不能被用来确认正式冲突。最终复核若仍判断冲突，且存在绑定到本次裁决所引用 `C` 的 `P`，该个案只能进入“待复核线索”；只绑定其它 `C` 的 `P` 不产生无关否决。
- 若语义复核已经找到适用于最终裁决所引用 `C` 的 `G/X`，而最终漂移复核仍判断冲突，两次模型判断存在分歧；该个案进入“待复核线索”，不能包装成正式问题。只绑定其它未被本次裁决引用观察的支持不会产生无关 veto。
- 超长单行或候选窗口被截断、语义支持超过最终复核容量、Token 或总 deadline 不足、Provider 超时/限流/失败、响应过大、JSON/字段/引用校验失败，或任何一批没有完整复核时，解释覆盖为 `partial`。在解释可能尚未查全时，即使最终模型返回冲突，也只能形成“待复核线索”。
- 没有找到相关候选且有界发现完整完成，不等于证明世界上不存在解释；它只表示本次授权冻结窗口内没有发现可用的 `G/X/P`。
- 单次反向行为和材料不足沿用产品决定，均进入“待复核线索”，不进入正式问题。

这些规则优先保护结果边界，代价是可能产生保守漏报或更多人工复核。提高敏感度不能绕过它们。

## 正式问题与待复核线索

两类结果必须在存储、接口和界面上严格区分：

| 结果层级 | 最低条件 | 接口与展示 | 计数 / 导出 / 反馈 |
|---|---|---|---|
| 正式一致性问题 | 完整且可回映的 `B+C`，所需事件独立性成立，解释搜索完整，最终判断为冲突，且不存在绑定到本次裁决所引用 `C` 的 `P` 或语义复核分歧 | `GET /api/v1/analysis-runs/{id}/issues` | 计入正式问题数；进入报告导出；可提交问题反馈 |
| 待复核线索 | 已有可核对双侧原文，但只有单次反向行为、材料/解释覆盖不足、存在与本次裁决所引用 `C` 相交的 `P`、语义支持与最终结论冲突，或其它晋升条件未满足 | `GET /api/v1/analysis-runs/{id}/review-clues` | 不计入正式问题数；不进入正式问题导出；不接受正式问题反馈 |

无法核对双侧原文的模型提案不能伪装成上述任一结论。未通过完整抽取校验的 `provisional-clues` 又是另一类未核实提案，仍须与角色“待复核线索”分开。

## 诊断与评测现状

运行诊断只记录内容无关的计数、覆盖状态和受控失败原因，例如候选数、已尝试/完成/失败批次、输出支持数、截断个案和 Token 用量；不记录候选原文或模型回答。解释路径失败不会把角色阶段伪装成“完整且无问题”。

仓库已经提供离线评测契约 [`scripts/ooc_eval_contract.py`](../scripts/ooc_eval_contract.py)，其作用是约束未来冻结评测，而不是一份评测结果。该契约将公开输入、私有 gold 和预测文件分离，校验世界/文档/内容哈希/可移植相对路径/轴/证据跨 split 与 group 的泄漏，要求私有标签经过双人标注与仲裁，并只允许使用不公开密钥的高熵 HMAC-SHA256 commitment 绑定 gold；公开 salt 不能阻止对小标签空间的离线枚举，因此被明确拒绝。评分器把缺失、`partial`、`failed` 和 `unassessed` 都按未正确处理，检查正式问题 precision、最差情形 recall、困难负样本 specificity、`B+C` 完整率、禁止引用、联合准确率、分现象误报、覆盖率和重复稳定性。

针对这份新契约，目前只有合同、评分实现和自动化测试；尚未为其提交由真实人工完成的封闭 holdout、真实模型预测或可发布指标。因此不能据此声称角色 OOC 已达到某个准确率、通过开放文本泛化或具备生产质量。契约自身可用以下命令回归：

```bash
python -m pytest -q tests/test_ooc_eval_contract.py
```

完整角色一致性信任边界见 [`character-consistency-v1.md`](character-consistency-v1.md)。
