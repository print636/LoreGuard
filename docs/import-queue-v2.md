# 文稿批量导入队列 V2

本功能改进文件导入与失败恢复，不更改 AI 一致性判断，也不自动确认资料身份、建立角色基线、发布章节或启动分析。

## 使用方法

项目中心的“导入已有故事”与工作台的资料入口使用同一套逐文件队列。可以分批选择 DOCX、Markdown、TXT、JSON，逐项选择文档类型和故事作用域。工作台还可明确指定替换哪个同名文档版本。

工作台上方的类型、作用域和版本选项只作为**之后新选择文件的默认设置**，不会悄悄改变已在队列中的文件。每项具体设置在队列行中展示；上传中、已经成功或结果待核对的设置不可直接修改。

两个入口保留各自用途：项目中心正在创建新项目，因此初始明确选择“参考材料／全局”，可逐份调整；工作台面对既有文档版本，初始不覆盖类型和作用域。作者未选择类型或作用域时，不向 multipart 请求写入这些覆盖字段。服务器既有行为是：同名文稿沿用旧版的类型和作用域，新文稿按故事正文／全局作用域导入。JSON 文件的原始内容不在前端重写；这不代表系统会从 JSON 自动确认账户中的文档身份。上传后仍需作者在资料工作台核对。

首次在项目中心点击“创建并导入”，确认收到项目 ID 后就绑定这个项目。页面留在队列供作者核对结果；“继续导入待处理文稿”复用已经创建的项目，只处理等待和明确失败的项。可以点击“进入已创建项目”继续管理资料。

## 状态与恢复

| 状态 | 含义与操作 |
| --- | --- |
| 等待导入 | 尚未提交；可以修改设置或移除。 |
| 上传中 | 当前单份文件请求进行中；不会重复点击提交。这里只展示逐文件阶段，不虚构网络字节百分比。 |
| 已导入 | 返回的文档 ID、项目 ID、文件名和版本已经核对；继续导入时不会重传。 |
| 导入失败 | 收到明确拒绝或本地参数不合法；解决问题后可以单份或批量手动重试。 |
| 结果待核对 | 网络中断、服务器异常、响应不完整或导入操作冲突，不能声称服务器没有保存。批量按钮不自动重试此项。 |

“安全重试同一导入”是作者明确发起的单项请求，复用原文件、完全相同的字段和稳定 `Idempotency-Key`。后端同一操作收据会返回原文档 ID／版本，而不是再生成一个版本。这个 key 是随机导入操作标识，不是模型 API Key。上传的文件字节不改变，前端不会自动重新尝试未知结果。

明确失败项修改类型、作用域或替换目标后，视为新的导入操作，会换新的 key。未知结果项须先安全重试或核对项目文档，不能直接改设置再悄悄提交新操作。“移出队列”不会撤销服务器文档；未知项移出前会提示：之后重新选择文件可能产生重复版本。

文稿成功导入但列表刷新失败，是**读取失败**，不会把成功项改成失败，也不会重新上传。遇到登录失效、权限拒绝或项目不存在时，本轮停止后续文件；应重新核对当前身份和项目。

项目创建尚未支持相同的幂等收据。如果创建响应丢失、服务器异常或没有可验证的项目 ID，页面显示“创建结果待核对”，禁止自动再建项目，不凭同名猜测归属。先查看项目目录，只有作者明确确认后才可放弃本次创建记录并创建另一个项目。中心的核对入口明确在新标签页打开文档／目录，使用 `noopener noreferrer`，原页的 File 和操作 key 不因此丢失；工作台核对则滚动到当前资料库。“进入已创建项目”仍是作者显式选择的同页导航。

## 本机文件与隐私边界

- File 对象、文件名、操作 key 和导入收据仅在当前挂载页面内存中，不写入 sessionStorage、localStorage、URL 或日志。
- 刷新、关闭、真正离开当前页面或会话失效后可能需要重新选择文件；不能承诺跨刷新恢复，也不能保证客户端取消会撤销服务器已经处理的请求。
- 队列未完成时离开会要求确认，刷新使用浏览器原生离开提示。工作台内部切换项目不会把旧项目文件自动绑定到新项目。
- 同一队列再次选择相同本地文件信息时只提示已在队列，不据此判断服务器上是否存在同名文稿。
- 已导入文稿的保管、访问权限及文档版本行为仍遵循项目后端；“移出队列”只是移除当前页面记录，不是删除文稿。

## 本轮验证边界

前端 helper 单元测试与 Mock-API 浏览器测试覆盖状态选择、稳定 key、参数修改、响应身份核对、部分失败继续、创建未知和两入口恢复。Mock 不连接真实数据库或模型，不证明真实文件解析、服务器迁移、AI 质量或生产负载表现；后端上传收据与并发合同由独立后端测试验证。
