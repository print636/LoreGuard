# 修订上传结果恢复与候选输入保护 V1

## 修订上传：同一操作，不制造重复版本

入口为已完成报告的“修订与复检”→“上传新版本”。仍使用现有文稿上传接口，不新增后端接口、存储系统或分析步骤。

深链打开时须先核验现有基线：只有状态为 `completed` 且包含冻结输入才允许选择文件、编辑上传字段和发送上传。读取期间或不满足条件时，字段及提交禁用，页面固定提示“基线尚未核验或不可用于复检”，提供返回基线/项目报告核对入口；发送函数也核验同一条件，不能绕过禁用状态发请求。跨项目、跨基线时仍执行原安全清空，不把先前选择的文件绑定到后来恢复的运行。

每次上传首次发送前，页面冻结以下内容：当前项目、基线运行、同一 `File` 对象、资料类型、故事作用域、精确替换文档 ID，以及展示用的目标名称和版本。操作生成一次 `Idempotency-Key`，失败后文件和语义未变时继续复用；文件、类型、作用域或替换目标改变时才建立新操作。故事作用域按现有规则规范化，空白作用域为 `global`，新增相关文档不发送替换 ID。重试不会仅凭同名猜测版本归属。

提交现有接口：

```text
POST /api/v1/projects/{project_id}/documents
Idempotency-Key: 本页生成的稳定操作 UUID
multipart: file, document_role, story_scope, [replace_document_id]
```

成功不能只看 HTTP 状态。响应须包含非空文档 ID、相同项目 ID、精确文件名和大于等于 1 的整数版本号；通过已有 `verifiedImportReceipt` 校验后才显示“上传已保存”。后端返回 `deduplicated=true` 时展示已核对原上传记录，不将重放说成新增版本。

### 状态与恢复

| 状态 | 页面行为 | 作者下一步 |
| --- | --- | --- |
| 尚未发送或明确失败 | 可以检查、更改输入；语义改变会生成新操作标识 | 修改原因后再次提交 |
| 上传中 | 固定本次文件、类型、作用域和替换目标 | 等待响应 |
| 结果待核对 | 网络中断、5xx/408、收据不完整或幂等冲突均不假称未保存；锁定原操作输入 | 在新标签页核对项目文档，或显式“安全重试同一上传” |
| 已保存、资料读取未完成 | 保留已校验收据，明确上传已经保存；禁止重复上传本次操作 | “重新读取项目资料”，仅重读，不发上传 POST |
| 已保存、资料已读取 | 显示版本收据，进入启动复检步骤；不自动启动分析 | 核对输入变化后自行启动复检；如需另传稿件，返回上传步骤点“上传另一份修订稿” |

未知结果不会自动重试，也不能通过更换当前表单的文件、类型、作用域或替换目标，把另一操作冒充安全重试。原操作收据获确认前，本页保持锁定。核对入口是指向当前项目文档页的 `_blank` 链接，带 `noopener noreferrer`，不会为核对而卸载原页文件和标识。

### 归属和隐私边界

- 回包应用前检查组件是否仍存在、项目与基线运行、请求代次及操作标识。切项目、切基线、注销或会话失效后，旧上传回包不能刷新新项目或跳转新运行；客户端中止等待不表示服务器撤销写入。
- 已保存后的资料重新读取仍使用父工作台既有访问控制和读取逻辑，只有父级返回明确成功才称资料已更新。
- 文件、冻结参数、收据和操作标识只在当前页面内存，不写 `sessionStorage`、`localStorage` 或服务器外的浏览器缓存。刷新、整页导航或卸载后不能恢复安全重试标识。未知状态下刷新后，应先核对项目资料；重新选择文件会建立新操作，不能承诺跨刷新去重。
- 不自动确认资料身份、定稿、发布、创建分析或改写旧报告。用户手动启动复检的既有入口与后端策略保持原样。

## 同批候选输入页内保护

候选审核保护尚未提交的备注、未创建作者轴的名称/定义/正向命题/适用情境、旧轴尚未保存的命题、尚未提交的轴选择、同向/反向和情境适用确认。默认表单和单纯切换“创建新轴”模式不被当成已输入草稿。

切换候选、候选分页、角色、档案栏目或应用内页面时，复用中央导航阻挡器确认。拒绝后 URL、候选选择和字段不改变，不发对应导航读取请求。原生返回/前进沿用已实现的单事件导航决策；刷新/关闭使用浏览器原生 `beforeunload` 警示，具体文案由浏览器决定。页面说明这些输入只在本页内存，不承诺跨刷新恢复。

会话失效仍强制离开未授权页面，不会被未提交备注阻挡。迟到的审核、建轴或旧命题保存回包按组件、候选实例/访问代次及请求代次核对，不能写入另一候选的输入。

成功提交审核后，只清除实际提交且未再变化的字段：驳回提交备注，确认还会提交轴选择、方向和情境确认。失败或迟到结果不清备注；提交期间产生的不同新输入不会被成功回包清掉。建轴或保存旧轴命题成功后，也只清其已写入且未再变化的字段。服务端已经创建的轴不会因离开或取消导航而撤销；刚创建轴的候选绑定仍需作者另行确认提交。轴列表冲突后的定义/方向重新核对约束保持原样。

本保护不添加浏览器持久存储、自动提交、自动确认、撤销已发生写入，也不扩展其它表单的产品策略。
