# 单次明确冲突与正式设定补漏

日期：2026-11-03。本阶段将网站判断对齐到作者已确认的规则：一次明确且证据完整的冲突可以成为正式问题，多次表现只增强证据。本文记录实现约束；真实模型与 CI 的最终结果见后续验证记录。

## 判断范围

新运行采用 `single-clear-event-v3`，checker 为 v5。候选准入、语义审查、最终晋升、报告证据和评测接入共同使用这套规则。

- 一次可以核对的相关表现就能进入审查。进入审查不等于冲突成立，结构化极性不直接决定正式问题。
- 正式问题至少依赖一个明确、实际发生、属于同一人物和比较项、适用对象与情境正确的冲突事件。材料、解释覆盖和原文引用仍须满足要求。
- 存疑表现保留为待复核线索。模型失败、引用失配或尚未审查的材料不能成为“正确无问题”。
- 报告描述该次表现与设定的关系，不把一次行为解释为人格已经永久改变，不生成改写文本。

## 逐事件响应与证据

主审模型必须返回新策略标识和逐事件判断。同一事件的多段描述归在同一组；当前候选引用必须各归属一组，不能重复或遗漏。最终结论只依赖被实际选中的完整事件，不要求其他不相关事件全部成为冲突。

服务端核对模型响应、成员集合与冻结来源，生成 `character-reviewed-events-v1` 记录，并让报告与诊断共用同一生成函数。记录绑定确认项、比较项、事件成员、引用顺序、文档版本、原文位置与内容摘要。评测器先核验这些记录，再投影结果；缺失、损坏或与原文不符时不回落为旧策略成功。

事件分组仍是模型的语义判断。来源绑定保证记录可以追溯，不独立证明模型的判断必然正确，也不因不同引用编号就认定发生了多次事件。已有的同事件承接与共享解释保护继续生效，不能靠拆组绕过解释。

## 解释与无问题的边界

在比较范围内，解释成立必须有适用的成长或例外证据，同时明确人物、特征、事实性与适用情境。解释材料不能消除主体或事实性本身的不确定。

若完整审查的所有当前事件都有明确依据排除在比较范围外，可以在不依赖成长解释的情况下判无问题。原始解释覆盖仍保留 `not_run` 或 `partial`，不会改写为“已经完成解释审查”。

目标覆盖 v2 为这种情况单独记录解释不必审查的依据，并绑定完整已审事件与目标观察集合。只有最终无问题、范围排除明确、整个相关池已审且来源有效时才能使用。正式问题仍要求真实解释覆盖；其他处理缺口、未知别名和截断仍会阻断。旧 v1 的含义不变。

有界审查未送入模型的反向观察会单独计数。它们不能被当成已经审过；全案无问题需要相关池完整，已明确的单事件问题仍可报告，同时保留整体未完成提示。

## 正式设定的有界补漏

原有抽取包通过校验，只能说明提交的记录有效，不能证明未提交的特征没有遗漏。本轮复用已有原文断言索引，检查尚未被有效记录或其真实身份／标签锚表示的片段。

存在可定位空缺时，每篇正式资料最多执行一次补充语义检查，随后仍经过原文、主体、稳定度与 scope 校验。已覆盖的文档不增加这次调用；多分块或主包重试不会重置文档级上限。关键词和姓名本身不生成新事实，补漏结果继续是待作者确认的候选。

补查用量计入现有预算。预算不足、超时、非法响应、未决判断或校验失败会保留部分覆盖与已有有效候选。它只增加发现常见漏项的机会，不证明全文语义穷尽，也不保证一个已表示片段中的所有特征都被发现。

## 版本与兼容

旧记录保持可读，新字段缺省时保留旧序列化。纯判断 helper 的旧协议入口用于兼容；网站所有实际调用显式选择新策略，早返回也保留该服务端标识。客户端和旧模型响应不能自行降级策略。

没有发生语义复核的“未发现反向表现”路径不会伪造已审事件；产品可以保留该状态，评测仍不将其自动计为已审无问题。服务器选出的 `server_evidence_pair_v1` 继续只表示待复核线索。

新响应结构采用有界输出预算；显式设置的小预算继续生效，无法容纳合同就明确跳过或降级。评分源码和质量门槛保持原样。

逐表现的成长关系方向、复杂跨事件解释闭包及下一次未揭盲人工验收仍属于后续阶段。本阶段的合成检查和 DEV 回归不替代独立质量验收。
