# LoreGuard 产品基础建设与体验架构 v1

状态：产品/UX 实施规格

日期：2026-09-19

适用范围：公开部署的真实多用户版本，个人工作区优先，为未来团队协作留边界
设计系统：[LoreGuard Master](../design-system/loreguard/MASTER.md)

## 1. 本阶段的结果定义

本阶段不是给现有单页再铺一层视觉皮肤，而是把 LoreGuard 从“能运行的技术工作台”改造成“用户愿意持续使用的故事审查产品”。完成后，产品应具备：

1. 可注册、登录、退出的真实账户；每名用户的数据在服务端隔离。
2. 登录后的项目中心，而不是直接进入一个充满技术信息的工作台。
3. 从创建/导入故事到发起校验、观察进度、阅读报告、反馈问题的连续旅程。
4. 每个核心页面都有 URL，刷新、前进、后退和深链均可预测。
5. 现有项目、文档、版本、运行、关系图、时间线、报告和 Provider 状态能力全部保留。
6. 延续“星轨虚拟书斋”，但信息密集区优先阅读效率；彩色“开始校验”是全产品唯一最高视觉强调。
7. 任何加载、失败、空数据、会话过期或模型降级都能告诉用户发生了什么以及下一步如何恢复。

本阶段成功的信号不是“页面数量增加”，而是新用户不读 README 也能完成第一次有效校验，老用户能快速回到最近工作，且不同账户不能看见彼此的任何资源。

## 2. 现状与设计约束

### 2.1 已确认的技术现状

- 前端为 React 19 + TypeScript + Vite 8 + plain CSS。
- 当前 `App.tsx` 以组件内状态切换 7 个视图，没有真实路由。
- 现有 7 个视图：文稿校验、项目与文档、版本对比、关系与时间、运行审计、完整报告、模型连接。
- 后端已经有项目、文档版本、分析运行、取消/重试、SSE、问题、反馈、关系图、时间线和版本对比等接口。
- 现有 UI 已经形成深靛、薰衣草紫、淡青、浅粉的视觉语言，并具有书灵、星轨和彩色“开始校验”按钮。
- 现有应用能力比页面组织成熟；产品单薄感主要来自缺少账户生命周期、项目入口、URL 导航和状态设计，而不是必须立刻扩充新的 AI 功能。

### 2.2 本规格采用的 Skill 结论

已按 UI/UX Pro Max 规则检测为 React/Vite 栈，并执行本地设计系统、React 栈、认证、导航、表单错误及空状态查询。采用的核心约束：

- 认证允许密码管理器、粘贴和自动填充，并提供密码显隐。
- 核心页面必须深链；浏览器返回键不能被组件内部状态破坏。
- 多字段错误既保留行内提示，也把焦点移动到可链接的错误摘要。
- 错误必须提供恢复动作；空状态必须引导下一步。
- 重型页面使用路由级懒加载，关系图和时间线不进入首屏主包。
- 响应式至少验证 375 / 768 / 1024 / 1440px，并额外以 360px 作为硬下限。

本地查询给出的浅色通用 SaaS 方案与既有艺术方向冲突，因此没有照搬；保留其可访问性与交互规则，视觉以既有“星轨虚拟书斋”为准。具体设计令牌已固定在 Master 文件中。

## 3. 目标用户与主要任务

| 用户 | 使用场景 | 主要目标 | 最怕发生的事 |
|---|---|---|---|
| 连载网文作者 | 每日更新后检查前文设定 | 快速找到明显冲突并回到原文修改 | AI 给出没有出处的主观评价 |
| 游戏剧情策划 | 多章节、多角色、多版本协作前审查 | 核对时间、知识、物品和规则状态 | 新版本混入旧文档或证据来源不清 |
| 编辑/审稿人 | 集中处理问题和标记反馈 | 筛选严重问题、审阅证据、记录处理状态 | 报告信息密度低、反复点开才能理解 |
| 首次体验者 | 用样例了解产品价值 | 在几分钟内看到一次完整且可信的结果 | 一进入就是复杂参数和开发者诊断 |

### 核心工作（Jobs to be done）

1. “当我导入一批故事材料后，我希望知道系统实际分析了哪些版本。”
2. “当系统声称有冲突时，我希望同时看到两侧原文、位置和判断边界。”
3. “当模型不可用或结果降级时，我希望知道哪些结果仍然可信。”
4. “当我改完文稿后，我希望看见旧问题是否解决、有没有新增问题。”
5. “当我下次回来时，我希望能从最近项目和最近报告继续，而不是重新建立上下文。”

## 4. 产品原则

1. **证据先于结论。** 报告页面的第一视觉任务是把问题和原文证据建立关系，不是展示 AI 光效。
2. **项目先于工具。** 用户先选择故事项目，再进入文档、校验和报告；Provider、诊断和版本细节不占据首次入口。
3. **确定性与 AI 边界可见。** UI 明确区分规则判断、模型抽取、AI 证据复核和降级结果，不把所有内容笼统标成“AI 发现”。
4. **一次只强调一个动作。** 当前页面有一个主要动作；全产品只有“开始校验”使用彩色渐变。
5. **渐进披露。** 首次用户看到导入、校验和报告；版本对比、关系图、运行审计在需要时展开。
6. **恢复能力就是体验。** 断网、SSE 重连、会话过期、模型失败和任务失败都必须可恢复。
7. **真实多租户。** 账户隔离是 API 查询边界，不是前端隐藏；跨工作区资源统一表现为不存在。
8. **安静的长时间工具。** 欢迎页可以有星尘和书灵，报告、编辑器、表格和关系图保持克制。

## 5. 信息架构

### 5.1 三层结构

```text
账户层
├─ 登录 / 注册
├─ 个人资料
├─ 安全与会话
└─ 模型连接设置

工作区层
├─ 项目中心
├─ 最近运行
├─ 待处理问题概览
└─ 工作区用量概览

项目层
├─ 项目概览
├─ 文档库
│  ├─ 活动版本
│  ├─ 历史版本
│  └─ 版本对比
├─ 校验台
├─ 运行
│  ├─ 实时进度
│  ├─ 运行详情/审计
│  ├─ 完整报告
│  └─ 关系图/时间线
└─ 项目设置
```

### 5.2 当前 7 视图的迁移映射

| 当前视图 | 新位置 | 产品解释 |
|---|---|---|
| 文稿校验 | `/app/projects/:projectId/check` | 项目内最高频任务 |
| 项目与文档 | `/app` + `/app/projects/:projectId/documents` | 拆成项目中心和文档库，降低首次复杂度 |
| 版本对比 | `/app/projects/:projectId/compare` | 文档库的二级能力，不再与校验同层竞争 |
| 关系与时间 | `/app/projects/:projectId/runs/:runId/visuals` | 明确属于某次冻结运行 |
| 运行审计 | `/app/projects/:projectId/runs/:runId` | 运行详情页，默认先展示用户可读摘要 |
| 完整报告 | `/app/projects/:projectId/runs/:runId/report` | 主要结果页面，可深链 |
| 模型连接 | `/app/settings/model` | 全局设置，不占项目主导航 |

现有功能不删除，只重组层级。迁移期间旧的组件状态可以作为兼容适配层，但最终 URL 是页面状态的权威来源。

## 6. 路由树

```text
/
├─ /login
├─ /register
├─ /forgot-password                         P1
└─ /app                                     需登录
   ├─ /                                     项目中心
   ├─ /runs                                 最近运行（P1 可独立成页）
   ├─ /projects/new                         新建/导入向导
   ├─ /projects/:projectId                  项目概览
   │  ├─ /documents                         文档库
   │  ├─ /documents/:documentId             文档及版本详情
   │  ├─ /compare?document=&from=&to=        版本对比
   │  ├─ /check                             校验台
   │  ├─ /runs                              项目运行历史
   │  ├─ /runs/:runId                       运行详情/审计
   │  ├─ /runs/:runId/report                问题报告
   │  ├─ /runs/:runId/visuals?tab=graph     关系图
   │  ├─ /runs/:runId/visuals?tab=timeline  时间线
   │  └─ /settings                          项目设置
   └─ /settings
      ├─ /profile                           账户资料
      ├─ /security                          密码与会话
      └─ /model                             模型连接
```

### 路由规则

- `/`：有有效会话则跳到 `/app`，否则跳到 `/login`。
- 未登录访问私有路由：跳转登录并保存 `returnTo`；登录成功后回到原目标。
- 无权限或其他工作区资源：服务端返回 404，前端展示“页面不存在或你没有访问权限”，不泄漏资源是否存在。
- `runId` 不属于 `projectId`：404，不自动纠正到其他项目。
- 报告筛选、排序、选中问题可以进入 query string；纯视觉展开状态不写 URL。
- 路由切换后主标题获得程序化焦点；浏览器返回恢复列表滚动和筛选。

## 7. 导航模型

### 7.1 桌面

**全局侧栏**保持稳定：

- 项目
- 最近运行（P1 前可在项目中心中呈现，不强制单独入口）
- 帮助
- 设置

进入具体项目后，侧栏在“项目”下显示项目内导航：

- 概览
- 文档
- 校验
- 报告
- 更多：版本对比、关系与时间、运行审计、项目设置

“更多”只收纳低频能力；报告若尚未运行则保持可见但显示解释性不可用状态，不静默隐藏。

**顶部栏**：

- 三层以上时显示面包屑。
- 项目切换器。
- Provider 状态（只显示可用/降级/未配置，点击进入模型设置）。
- 用户菜单：账户设置、退出。
- “开始校验”只在存在活动文档的项目页显示；在校验页为最高强调，其他项目页为快捷入口但仍保持同一动作语义。

### 7.2 移动端

项目内底部导航最多 5 项：概览、文档、校验、报告、更多。图标必须同时有文字标签。

- 顶部栏保留返回/项目名/用户菜单。
- Provider 状态进入“更多”，不挤占首屏。
- 校验页允许固定底部“开始校验”，正文预留安全间距。
- 关系图默认先显示可读列表摘要，用户选择后再打开全屏图形视图。

## 8. 用户旅程

### 8.1 首次用户：注册到第一份报告

```text
注册账户
  ↓ 自动创建个人工作区
项目中心空状态
  ├─ 导入已有故事（推荐）
  ├─ 新建空项目
  └─ 打开原创样例
  ↓
确认项目名与文档用途
  ↓
文档解析与活动版本确认
  ↓
校验选项（默认推荐值，图/时间线为可选）
  ↓
开始校验 → SSE 阶段进度 → 可取消
  ↓
报告摘要 → 问题证据 → 接受/误报/已解决
```

关键要求：

- 注册表单只收集邮箱、密码和显示名；显示名用于个人工作区和账户入口。
- 成功注册后不再次要求用户输入相同信息。
- 项目创建向导只展示当前步骤需要的字段。
- 文档上传明确支持 DOCX、Markdown、TXT、JSON。
- 首次校验前解释“世界观设定不是必需；直接导入故事正文也可以分析”。
- 关系图和时间线默认关闭，由用户在校验选项中选择；设置记忆到项目，但每次可覆盖。
- 报告完成后直接进入报告，不把开发者诊断当作成功页。

### 8.2 返回用户：继续最近工作

```text
登录
  ↓
项目中心：最近项目 / 进行中的运行 / 待处理问题
  ↓ 单击项目行
项目概览：上次运行摘要 + 活动文档 + 继续操作
  ├─ 查看最近报告
  ├─ 导入新版本
  └─ 再次校验
```

### 8.3 失败恢复

```text
运行中断
  ├─ 浏览器断线 → SSE 自动重连 + 显示“正在恢复进度”
  ├─ 模型失败 → 规则结果保留 + 标记“模型增强未完成”
  ├─ 任务失败 → 显示原因摘要 + 使用冻结输入重试
  ├─ 会话过期 → 保存当前草稿 + 登录后回原页面
  └─ 用户取消 → 运行保留为 cancelled，可查看和重试
```

### 8.4 多用户隔离旅程

- 用户 A 登录后只列出 A 所属工作区的项目。
- A 猜测 B 的项目、文档、运行、问题、反馈或 SSE URL，均得到相同 404 表现。
- 前端切换账户时清空内存缓存、SSE、选中的项目和本地草稿命名空间。
- 退出后使用浏览器返回不能重新显示敏感页面；缓存页面必须重新确认会话。

## 9. 页面职责与状态

### 9.1 登录 `/login`

**职责**：建立服务端会话并返回原目标。

内容：邮箱、密码、密码显隐、保持登录说明、登录、注册链接、忘记密码（P1 前可显示“暂未开放，请联系管理员”但不可伪装可用）。

状态：

- 默认、提交中、字段错误、凭据错误、速率限制、服务不可达、会话已经有效。
- 凭据错误使用统一文案，不泄漏邮箱是否注册。
- 允许粘贴、自动填充和密码管理器；不得在客户端日志输出密码。

### 9.2 注册 `/register`

**职责**：创建用户、个人工作区和初始会话。

内容：邮箱、密码、确认密码、显示名（可选）、服务条款确认（若公开服务需要）。密码规则在输入前可见，不用“猜规则”。

状态：邮箱已用、密码不合规、速率限制、创建部分失败。账户与工作区创建必须事务化；不能出现账户成功但工作区缺失的半成品状态。

### 9.3 项目中心 `/app`

**职责**：成为登录后的主页，帮助用户恢复上下文或开始新项目。

首屏顺序：

1. 页面标题、搜索、新建项目。
2. 若有进行中任务，显示稳定的运行条而不是弹窗。
3. 最近项目列表：项目名、活动文档数、总字数、最近运行状态、未处理问题、更新时间。
4. 最近报告/运行摘要。
5. 用量摘要放在次要区域，不抢占故事工作。

项目集合优先使用行式列表或具有明显层级差异的两列布局，不把每个统计数字拆成独立卡片。

空状态：书灵可以出现；三个入口分别为“导入已有故事”“新建空项目”“打开原创样例”。只有一个视觉主按钮，其他为普通动作。

### 9.4 新建/导入向导 `/app/projects/new`

**职责**：以最少输入建立可校验项目。

步骤：

1. 选择开始方式：已有文稿 / 空项目 / 原创样例。
2. 项目名与可选说明。
3. 文件及用途：故事正文、设定资料、其他参考；未提前设置世界观也可以继续。
4. 解析确认：文件名、格式、字数、识别到的用途、冲突处理。
5. 完成后进入项目概览或直接开始校验。

上传失败按文件展示原因和重试，不让一个文件失败抹掉其他成功文件。

### 9.5 项目概览 `/app/projects/:projectId`

**职责**：回答“这个项目现在是什么状态，我接下来做什么”。

内容：项目名和更新时间、活动文档摘要、最近一次运行、问题分布、尚未处理问题、下一步动作。没有运行时引导校验；有新文档版本时提示是否重新校验。

不在此页直接铺开所有抽取记录、Agent 轨迹或模型诊断。

### 9.6 文档库 `/documents`

**职责**：管理分析输入及版本。

内容：活动文档列表、用途、版本、字数、更新时间、导入/替换；展开或进入详情后查看历史版本。删除采用软删除/停用语义并允许撤销；永久删除进入项目设置的危险区域。

状态：无文档、上传中、部分失败、解析失败、格式不支持、版本替换成功。

### 9.7 文档详情 `/documents/:documentId`

**职责**：预览正文、查看版本链和元信息。

内容：文档预览、当前活动版本、历史版本、来源格式、行数/字数、在最近运行中是否被使用。P1 可加入文档内搜索与版本恢复。

### 9.8 版本对比 `/compare`

**职责**：比较同一文档的两个版本。

内容：版本选择、增删/未变摘要、差异块、截断警告。选择器只列同项目、同名文档的合法版本。差异过长时分段加载，不能让一个大文件锁死页面。

### 9.9 校验台 `/check`

**职责**：确认输入和分析选项，发起一次冻结运行。

布局：

- 活动文档清单与版本；明确本次会冻结哪些输入。
- 校验选项：默认“问题报告”；关系图、时间线为可选；高级模型能力折叠显示并标注可用性。
- Provider 摘要：可用、未配置、降级；不显示 Key。
- 估算范围：文档数、字数、可能的 Token/费用（价格未配置时明确“不提供估算”）。
- 彩色“开始校验”是唯一最高强调。

开始后：同页显示阶段化进度，包含抽取、检索、规则检查、证据复核、生成报告等真实阶段；支持取消、断线恢复和后台继续。用户可以离开页面，顶部保持运行状态。

### 9.10 运行历史 `/runs`

**职责**：查看每次冻结输入的状态和结果入口。

字段：开始时间、输入版本摘要、状态、耗时、问题数、模型覆盖、Token/成本、发起者。支持状态筛选和分页；50 条以上不一次性渲染。

### 9.11 运行详情 `/runs/:runId`

**职责**：先给普通用户看可读运行摘要，再渐进披露技术诊断。

首屏：状态、阶段、输入快照、耗时、模型是否参与、是否降级、问题/待澄清数量、查看报告、取消/重试。

“开发者详情”折叠区：抽取记录、Agent/Reviewer 诊断、运行 ID、重试谱系。开发者字段不能成为理解运行是否成功的前提。

### 9.12 报告 `/report`

**职责**：完成问题审阅和反馈，是 LoreGuard 的核心价值页。

结构：

- 顶部摘要：确认问题、待澄清、已处理、模型覆盖和降级说明。
- 筛选：类别、严重度、反馈状态、关键词；筛选写入 URL。
- 左侧/列表：问题标题、类别、严重度文字、置信度、处理状态。
- 主阅读区：结论、两侧原文证据、文档/行号、为什么冲突、修订建议、AI 证据复核注释。
- 操作：接受、误报、已解决、重新打开；反馈后显示历史。

空状态必须区分：

- 尚未运行：引导开始校验。
- 运行中：显示进度并允许离开。
- 完成且 0 个问题：说明覆盖范围和模型/规则状态，不宣称故事绝对无误。
- 筛选后 0 条：清除筛选。
- 报告加载失败：重试，不丢失当前筛选。

### 9.13 关系图与时间线 `/visuals`

**职责**：辅助探索某次运行的记录，不作为报告的必经步骤。

- 明确显示数据来自哪个 run。
- 未请求生成时显示“本次未生成”，并给出下一次校验的设置入口。
- 大数据警告、节点/边截断和无时间记录必须可见。
- 图形有列表/表格替代；键盘用户不依赖拖拽才能获取信息。
- 平板与手机先显示筛选后的列表，再由用户进入全屏可视化。

### 9.14 模型设置 `/app/settings/model`

**职责**：解释模型能力与连接状态，而不是让 Provider 细节渗透所有页面。

当前 V1：每个账户可保存一份 OpenAI-compatible 聊天 Provider。API Key 在服务端以独立 AES-256-GCM keyring 加密，前端只写不读，支持替换、删除、最小连接测试和乐观 revision；分析运行冻结具体配置版本，历史页显示计划来源与实际执行状态。Key 禁止进入 `localStorage`、URL、前端日志或错误正文，Provider origin 由部署管理员显式 allowlist。Embedding/RAG 凭据仍是部署级配置。

### 9.15 账户与安全设置

- 资料：显示名、邮箱（邮箱变更 P1）、语言/时区（P1）。
- 安全：修改密码、当前会话、退出当前会话；退出所有设备和恢复流程为 P1。
- 危险区域：删除账户（P1，需数据导出/冷静期方案后再开放）。

## 10. 全局状态规范

| 状态 | 显示方式 | 用户动作 |
|---|---|---|
| 应用启动 | 保持骨架尺寸稳定，先验证会话 | 无 |
| 页面加载 | 页面级骨架；不清空已显示的旧内容 | 可继续浏览旧内容 |
| 局部保存 | 控件内进度，防止重复提交 | 等待/取消（适用时） |
| 离线 | 顶部持久条，说明只读或不可执行范围 | 重试 |
| API 不可达 | 页面内错误，保留导航和草稿 | 重试、查看状态 |
| 会话过期 | 保存草稿后打开重新登录流程 | 登录并返回 |
| 429 | 显示等待时间或建议，不无限自动重试 | 稍后重试 |
| Provider 未配置 | 非阻塞提示：规则基线仍可运行 | 前往模型设置 |
| Provider 降级 | 运行/报告中标记受影响阶段 | 检查连接、使用冻结输入重试 |
| SSE 断线 | “正在恢复进度”，指数退避 | 手动重连/查询状态 |
| 运行失败 | 原因摘要、输入快照仍可查看 | 重试、复制诊断 ID |
| 无权限/跨租户 | 统一 404 页面 | 返回项目中心 |
| 未知错误 | 友好摘要 + 关联 ID；不显示密钥/原文 | 重试、复制关联 ID |

Toast 只用于“保存成功”“反馈已记录”等短暂确认；认证失败、上传失败、分析失败和字段错误不能只用 Toast。

## 13. 视觉与内容策略

### 13.1 保留

- 深靛底色、薰衣草紫/淡青/浅粉的品牌识别。
- 彩色“开始校验”按钮。
- 书灵作为产品角色，但只在欢迎、空状态和帮助中出现。
- 证据、状态和运行数据的技术可信感。

### 13.2 收敛

- 报告页减少玻璃模糊和泛光，用清晰边界、分栏和层级建立秩序。
- 移除没有信息含义的英文眉题、满屏星形符号和重复渐变。
- 统计数字合并为摘要带，不为每个数字单独建同款卡片。
- 书法/楷体只用于短标题，表格、表单和正文统一可读中文无衬线。

### 13.3 唯一记忆点

“开始校验”是书斋中开启审查流程的“星轨印记”：粉—紫—青渐变、极轻的光晕、运行时变为稳定进度，不做循环闪烁。其余按钮不复用该效果。

## 14. 真实多用户 UX 合同

这里定义前端可观察行为，具体安全实现由后端规格负责。

- 注册成功时自动创建个人工作区；用户不需要理解“workspace”才能开始。
- 项目属于工作区，文档、运行、问题、反馈通过项目/运行关系继承租户边界。
- 会话使用安全 Cookie；前端不读取令牌，不将认证凭据存入 `localStorage`。
- 修改数据的请求具有 CSRF/Origin 防护；前端遇到 CSRF 失败显示重新加载/登录动作。
- 每个账户的本地草稿、最近项目和界面偏好用用户 ID/工作区 ID 命名空间隔离。
- 退出立即关闭 EventSource、清空查询缓存和敏感内存状态。
- 模型 API Key 不在浏览器回显或 Web Storage 留存；账户级 BYOK 已以加密 revision、审计元数据和运行冻结身份落地，Embedding 凭据仍由部署端管理。
- 个人工作区数据隔离是 P0；团队邀请、角色权限和共享项目是 P1/P2，不在本阶段伪造入口。

## 15. P0 / P1 边界

### P0：本阶段必须交付

#### 工程地基

- 引入真实客户端路由、受保护路由和路由级懒加载。
- 把单体 `App.tsx` 拆为应用壳、页面、领域模块、基础组件和 API 客户端。
- 统一请求错误、Toast、确认对话框、Error Boundary 和会话失效处理。
- 保留现有七视图全部能力并迁移到新 URL。

#### 账户与隔离

- 注册、登录、退出、当前用户查询、个人工作区自动创建。
- 服务端会话、安全 Cookie、密码哈希、CSRF/Origin 防护、认证限流。
- 项目、文档、版本、运行、SSE、问题、反馈、关系图、时间线、对比接口全部工作区隔离。
- 两个测试用户的正向访问与跨租户 404 自动化测试。

#### 产品体验

- 项目中心及空状态。
- 新建/导入基础流程，可直接导入故事正文。
- 项目概览、文档库、校验台、运行详情、报告、设置页面。
- 关系图/时间线按次运行、可选生成，不成为主流程阻塞项。
- 加载、空、失败、离线、会话过期、429、Provider 降级和 SSE 重连状态。
- 360/375/768/1024/1440 响应式和键盘可用性。

#### 视觉

- 按 Master 令牌整理现有四层 CSS，不在功能组件中散落原始颜色。
- 保留星轨书斋风格；彩色按钮唯一；书灵仅限欢迎/空/帮助。
- Lucide 或同一套自维护 SVG 图标；不使用 emoji 作为结构图标。

### P1：P0 稳定后再做

- 忘记密码、邮箱验证/变更、退出所有设备、会话列表。
- 项目搜索增强、排序、归档、复制、软删除与撤销。
- 文档内搜索、版本恢复、批量操作和大列表虚拟化优化。
- 报告导出、修改前后问题对比、项目累计成本趋势。
- 多 Provider、按项目覆盖、团队共享密钥和自助新增 Provider origin；当前 V1 只支持每账户一份聊天 Provider。
- 团队邀请、角色权限和共享工作区。
- 更完整的新手任务清单和上下文帮助。

### 明确不做

- 为了“功能丰富”加入故事续写、视频生成或通用聊天机器人。
- 多智能体聊天大厅或无限节点工作流画布。
- 没有后端行为的设置项、按钮和占位页面。
- 在 P0 中实现计费、社区、作品广场或实时多人编辑。

1. 建立设计令牌、路由壳、API Client、错误/Toast/Error Boundary

4. 将现有 7 视图逐一迁入项目路由，旧状态适配后删除

6. 视觉收敛与页面截图评审

路由与认证不应在同一个“大爆炸”提交中替换全部工作台。每迁移一个页面，旧端到端流程仍可运行；最后才移除旧单页切换。

## 17. 验收标准

### 17.1 账户与安全

- 新用户可注册、自动进入个人工作区、退出并重新登录。
- 密码允许粘贴、自动填充和密码管理器；存在显隐控制。
- 用户 A 不能通过列表、直接 UUID、SSE、版本对比、问题反馈或关系图访问用户 B 的数据；全部返回同口径 404。
- 退出后浏览器返回不显示缓存的敏感数据。
- Key、密码、故事正文、Prompt 和模型原始响应不进入前端日志或 URL。

### 17.2 导航与状态

- 当前 7 个视图均有稳定 URL；刷新后保留正确项目、运行和页面。
- 浏览器前进/后退可预测；报告筛选和选中 run 可恢复。
- 任一异步动作都有等待、成功、失败和恢复路径。
- SSE 断线重连不会把失败显示为完成，也不会重复提交运行。
- 会话过期后登录可返回原页面，未提交长文本草稿不丢失。

### 17.3 核心流程

- 首次用户不用 README 能完成“注册 → 创建/导入 → 校验 → 报告 → 反馈”。
- 没有世界观文档时仍可仅用故事正文发起校验。
- DOCX、Markdown、TXT、JSON 支持范围在上传前可见。
- 用户可选择是否生成关系图和时间线。
- Provider 不可用时，页面明确说明规则基线仍运行以及哪些增强缺失。

### 17.4 视觉与响应式

- 360、375、768、1024、1440px 无页面级横向滚动和操作遮挡。
- 200% 浏览器缩放下核心任务仍可完成。
- 键盘可以完成登录、项目选择、上传、发起/取消校验、报告筛选和反馈。
- 普通文字对比度 ≥4.5:1；组件边界和焦点 ≥3:1；严重度不只依赖颜色。
- `prefers-reduced-motion` 下没有漂浮粒子/呼吸闪烁，内容立即可用。
- 书灵只出现在欢迎、空状态和帮助；彩色渐变只出现在“开始校验”。

### 17.5 性能与工程

- 图、时间线和版本对比采用路由/功能级懒加载，不阻塞登录和项目中心。
- 50 条以上的运行/问题/文档列表分页或虚拟化。
