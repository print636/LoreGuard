## 当前共同入口

行为选择器已经允许从冻结窗口选择最多两条连续行为路径；选择本身不证明行为成立。独立 V16 仍同时要求角色、现实性、对象、语义轴与方向成立。被拒项不能直接转为负向观察，也不能消除原主张的未决材料。

现有独立情境说明不要求证明冲突，却先由固定用途词和动作语法筛选窗口，并要求用途落在同一动作分句。课堂的后续用途说明或普通教学连续动作可能因此没有调用。扩大一个动词或用途词表不能解决这个共同边界。

两人同句的旧直接绑定器不会用联合主体机械授权后续单数代词；独立语义核实仍可在完整窗口内判断归属。需要分清“无法确定是谁做的”与“内部执行失败”。本阶段不以强制显名或过滤全部多角色材料替代真实判断。

## 已批准的最小合同

复用现有最多一次独立片段情境说明调用，使用新运行冻结的 v2 合同；旧任务继续 v1。将候选准备改为有界来源窗口，不按动作或用途词白名单决定是否能核实。模型在完整行及相邻上下文中判断实际角色、动作、完整受事、用途及每个作者确认情境的关系，选择原文片段；服务端验证来源、索引、唯一定位与数量上限。

仅在上述语义明确且属于全部确认情境之外时，生成现有 `habit_scope_refs_v1` 引用：只保存确认候选与基线输入 ID、基线摘要及证据序号、新稿输入与文档 ID、内容摘要、原文行号、动作和用途的起止位置，以及引用自身摘要；不复制原文内容。报告依据这些定位校验并展示双侧冻结原文。引用字符位置以 Python Unicode code point 计算。来源分开和定位成功不等于语义正确；未确定、换物、错人、否定或兼用未厘清都不能生成范围外结论。真实排演或教学行为可以事实发生，不能仅因其用途而当作虚构事件。

该说明只覆盖指定片段：不造负极性、不创建正式问题、不改写 V16 历史，不消除原主张债或宣称全稿完整。公开 DTO 与布局不变；调用数、任务预算、取消与旧重试边界沿用。若要求中性行为也进入正式主审池，需要另行明确观察协议，不在此片段说明中暗中扩展。

冻结入口沿 `batch_coverage.habit_scope_policy`：新授权深审写 `habit-scope-review-v2`；worker 只恢复精确版本。旧 v1 仍走原 prompt 和语法入口；无字段的旧任务不获得新能力。私有运行字段 `_character_habit_scope_review_policy` 不接受客户端注入，原 v1 私有开关只保留旧兼容。

新目的常量为 `character_habit_scope_review_v2.HABIT_SCOPE_SYSTEM_PROMPT_V2`。一次请求至多两个、每个至多 600 字的完整原文行，同时保留相邻完整行；候选需要已授权角色或别名的来源锚点，不要求动作再出现同名角色。输出 `schema_version/request_digest/items`；每项有 `id`、角色／现实性／受事相关性／用途所属／更正关系枚举，`action_quote/object_quote/purpose_quote`，以及按原序覆盖全部确认情境的 `contexts[{index,relation,basis_quote}]`。所有引文由服务端唯一定位；不让模型计算偏移。依据可为带角色省略的原文片段，语义由模型结合完整上下文判断，不以引文字面相同代替同指。

仅全部必要语义明确、每个情境均为 `outside` 时才输出范围外引用；`inside/uncertain` 和无行为均不输出此说明。引用的 action 范围是动作与用途依据的最小连续包络，保留全文 reader。前后文帮助判断否定、转述、纠正及用途承接，但本版可显示引用仍限定在同一原文行；无法在这一范围定位的依据保留未决。

v2 输出预留为 `min(原 character_drift_max_completion_tokens, 2048)`，v1 仍为 512；每次最多一个逻辑请求、一次尝试，按实际预留做 token 准入，沿原阶段总预算和共享期限。没有额外纠正轮次。超限和未选择不代表覆盖完成。

受控验收集中覆盖普通跨分句用途、合理省略、双主体不确定／明确他人、否定与换物、逐情境未知、完整来源和重复引文、预算与版本隔离；加一条实际 stage→引用路径，保留原观察和覆盖计数。旧作用域及既有 reader 专项回归。受控语义槽只验证协议防线，实际模型是否正确判断由本阶段固定真实批另报。

## 真实执行阻断的有界重建与修复

仅复用本批公开冻结目标、实际已接纳观察及已保存的 `extraction_return`，离线运行原 Stage 的下游流程；不发模型请求、不写旧 DB。重建在 `ClaimResolutionManager.repairs_targeted` 转换目标时复现 `ValidationError`（安全记录仅 `loc=[] / type=value_error` 和源码位置）。这是实际下游对象重建，不是原模型全响应的完整回放：原提取诊断、正式来源提取与私有支持绑定未完整重放，后续主审也没有据此产生真实结论。收据位于 `artifacts/story-workbench-stage/author-trial-recovery/admitted-stage-reconstruction.json`。

可证代码条件是：该目标没有任何本来源、本确认候选的消债收据，恢复检查仍把普通 `behavior_boundary` 召回目标强转为较窄的 V3 语义核实目标。冻结目标没有第一类 `key_object` 或批准轴；既有对象恢复合同因此返回空对象，而 V3 DTO 要求该类型具备对象。普通召回本身不承诺具备这种协议证书，不应仅为询问“有没有已解决的缺口”而强制转换。

最小修复只改 `repairs_targeted`：先检索本来源及确认候选的真实收据，没有则返回未修复；随后通过同来源、与收据目标摘要相符的已绑定观察建立可恢复目标身份，再逐一核对同目标所有尚未完成的抽取包，包括没有接纳观察的验证包。召回证据定位范围不改变目标身份，其他目标字段仍须相同。未知或未枚举的包、未证实缺口仍阻挡恢复；完整枚举且没有剩余缺口的包不制造历史债。原目标必须与绑定一致，所有终态缺口仍须逐项有对应证明。对象必填、批准轴、原主张、来源/目标隔离及缺口完整性要求均不放宽，不造对象、不捕获校验异常后当成功、不增加模型调用。旧没有消债凭据的运行得到正常未决结果，不获得新的语义认证。
