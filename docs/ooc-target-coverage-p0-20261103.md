# 角色审查的目标覆盖与线索证据适配

日期：2026-11-03。范围：修复首轮封闭基线发现的运行记录与评测接入问题；不是角色判断策略升级，也不是一次新的独立封闭验收。

## 改变了什么

角色审查阶段继续保留整体的部分覆盖状态，同时为每条已确认的角色比较项生成 `target_coverage` 来源记录。记录绑定确认项、比较项指纹、材料与解释覆盖、分块处理计数以及未解析角色的归属。

评测器只在其他角色有正式来源身份、当前行为能绑定到该角色、冻结别名无歧义且没有任何其他处理缺口时，接受该比较项的局部完整结果。仅仅名字不同不构成证明；未确认昵称、代词歧义、身份来源缺失、目标自身缺材料或后续审查失败仍会拒收。缺少新版记录的旧结果继续使用原来的严格检查。

后续审查产生的覆盖缺口单独记录，不会因为全局状态已经被其他角色标为部分覆盖而丢失。本轮只允许排除能够证明无关的别名阻断；尚未实现任意其他角色失败的完全隔离。

合法的待复核线索新增 `server_evidence_pair` 来源记录，由服务端从冻结的设定证据 B 和当前表现 C 共同生成。报告与诊断必须携带相同记录，执行器核对上传后的文档身份、版本、完整内容摘要、行号及原文引用后才投影。当前稿件的上传身份也纳入映射。

这种记录只能形成待复核线索，不会伪造模型审查句柄、已审查事件或正式冲突。正式问题的原有模型引用校验保持生效。旧预测的序列化不补空字段，保留既有摘要与读取兼容性。

## 验证安排与边界

先以合成材料检查生产端与消费端贯通：合法线索、无法确认的角色身份、未找到目标表现、后续处理缺口，以及真实 HTTP 调用路径的文档身份传递。集中检查后只补跑失败或受影响项目。

真实模型验证使用原公开批次中的三个已揭盲样例，独立实例、数据库与执行身份，固定本轮源码及运行配置。该执行只验证实际链路和来源记录，不读取人工答案、不进行新一轮质量评分。模型输出可能变化，不能要求某个样例一定走指定分支。

首轮 18 题原始模型报告、正式评分和人工材料保持原样。修复后的同题结果属于 DEV 回归，不能称为新的盲测，也不能由合成测试通过推断开放文本准确率。

CI 的整站端到端任务总时限从 10 分钟调整至 15 分钟，原因是既有依赖安装已占用大部分原时限。断言、测试步骤及其他任务不变；这个调整不是性能提升结论。
