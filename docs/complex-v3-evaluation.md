# 复杂原创验收集 v3

## 定位

`evaluation-complex-v3` 是 LoreGuard 自有的固定验收回归集，采用原创世界观“潮痕群岛”。它不包含商业游戏 IP、公司内部资料或 ConStory-Bench 内容。

这套数据由开发者编写、开发者可见，没有独立标注者，也不是盲测。其用途是验证跨文档状态语义、证据定位和规则回归，不能作为开放长篇故事或生产环境准确率的估计。

## 数据构成

- 14 个多文档案例，每例至少 4 份文档，共 10 个固定预期问题。
- 一个集成失败案例在 5 份文档中同时布置五类问题，并混入不参与判断的叙事信息。
- 每个预期问题固定类别、证据文档和 1-based 行号；评分不会只比较“是否出现某类问题”。
- 五类问题均包含正例和困难反例。
- 数据内容、版本、SHA-256 和限制声明记录在 `data/evaluation-complex-v3/manifest.json`。

覆盖点如下：

| 能力 | 正例 | 困难反例 |
|---|---|---|
| 事实状态 | 无时间限定的权威状态互相矛盾 | 前后状态有时间，并存在中间解除命令 |
| 时间线与地点 | 同一分钟出现在相距较远地点 | 城市与城内房间的嵌套地点；角色绑定的有效传送许可 |
| 知识来源 | 明确获知事件晚于角色引用 | 更早的密函来源链；档案缺失但没有“后来才获知”的证据 |
| 物品状态 | 非持有人在无交接记录时使用关键物品 | 新持有人在明确交接后使用 |
| 世界规则 | 同 actor、scope、action 的规则违反 | 同角色有效例外；限制区域以外执行同一动作 |

## 固定无模型结果

运行：

```powershell
python scripts/run_complex_v3_evaluation.py
```

当前 `BaselineExtractor + DeterministicCandidateNormalizer` 结果：

| TP | FP | FN | Precision | Recall | F1 | 精确证据对命中率 |
|---:|---:|---:|---:|---:|---:|---:|
| 10 | 0 | 0 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |

运行器显式构造 `BaselineExtractor`，不会读取模型 Provider，也不会调用外部模型。报告会写入 `artifacts/complex-v3-evaluation.json`，并记录 `model_enabled=false` 和 `provider_calls=0`。

`complex-v3-fact-state-transition` 曾暴露自然语言事实没有携带句首时间的问题。修复后，句首精确时间会进入统一事实记录，规则层按不同时点的状态迁移处理，而不是针对“冻结/生效”等具体词语写特例。该困难反例保留为回归入口。

## 边界

这套验收集可以支持以下项目事实：LoreGuard 已建立原创、多文档、固定证据行的开发回归集，并能报告精确率、召回率、F1 和证据定位命中率。它不能支持“经过人工盲测”“开放文本准确率达到 90%”或“已验证商业游戏全量剧情”等表述。
