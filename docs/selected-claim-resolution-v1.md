# 新行为路径与原抽取记录的关联核实

本功能处理一种流程缺口：系统第一次概括的行为尚未核实，后来已经从原文发现并接纳了相关动作，但两份记录还没有建立可靠对应。仅因为位于同一行、提到同一个人物，不能把原来的疑点直接清除。

“原抽取记录”是系统最初概括的那句话；“新行为路径”是后来从原文分句中选出、经过独立核实并实际接纳的动作。关联核实只判断两者是否对应，不直接判定角色是否违反设定。

## 核实什么

本功能处理尚未解决的情境习惯原抽取记录。例如，原记录是“连试音都省了便示意开场”，后来接纳的路径是接过麦克风、摆放、略过试音。原记录是否填写物件，不应决定能否利用这条已经核实的新路径。

系统保留原来的文字、情境、物件字段和身份，不补写名词，也不改成另一句更容易接受的话。物件为空时仍保持为空；原记录已有物件时，独立核对它与动作实际对象的关系。在已有调用额度内，可以把这份原记录、实际接纳的新路径及获授权的完整冻结窗口交给模型独立核实：

- 原记录的全部含义是否由该动作及上下文支持，而非只支持其中一部分。
- 人物、动作是否实际发生、物件承接和引用是否仍然成立。
- 原记录填写的物件是否确指该动作的对象；只是同类名词或附近出现的另一件东西，不能直接当作同一个对象。允许有上下文证据的语义对应，不要求名称逐字相同。
- 在提供的完整窗口内是否能明确对应到这一事实，还是有其他合理对应或信息不足。

允许语义等价，不要求逐字重复。这里的唯一对应只指该次提供的原文范围，不能推断整篇故事只有这一件事。模型无法确认、窗口存在遗漏或有多种对应时，继续保留未决状态。

这一能力有入口边界：必须已经保留原记录，且存在实际接纳的新路径。旧初始抽取对某些未在原文逐字出现的物件别称仍可能提前拒绝记录，例如原文写“麦克风”、抽取填写“话筒”；这种记录目前尚不能进入本核实流程。新协议的语义对应支持不能据此外推为整个抽取链已支持任意别称。后续应使有可靠来源的此类记录进入待核实流程，而非仅因名称不相同直接丢弃；本轮不改这一前置入口。

## 怎样解除旧疑点

只有独立关联核实通过，并且相关观察经过正常接纳及持久化核对，才能解除对应原记录的缺口。新行为被选择、模型回答“支持”、引用可定位，各自都不足以单独完成这一过程。

处理按来源、作者已确认的角色设定和比较目标隔离，不清除其他角色或另一条记录的疑点。某个目标的最终材料覆盖恢复后，仍要由既有主审结合情境和解释材料决定是否形成正式问题。原调用失败的历史记录保留，整稿可能仍然部分覆盖。

新策略优先使用实际接纳的新路径核实尚未解决的原记录。没有符合来源与目标要求的新路径时，按原有能力决定是否进行旧复核。新旧两条路线共用每个确认目标在一次运行中至多一次复核机会，不能在新核实失败后又追加旧复核。新关联协议不做结构合同重放；旧路线保持原有的有限纠正机制。复核机会不等于底层 HTTP 次数，已有传输重试仍按实际发生计量。剩余 Token、时限和取消检查继续生效。

## 兼容与来源记录

新运行在已有角色深度审查授权基础上冻结策略版本。首版策略使用 V17，只处理物件为空的原记录；其已存任务重试仍保留这一规则。第二版策略使用独立 V18 协议，允许原物件为空或非空，并显式核实原物件与实际对象的关系。更早没有该策略的任务同样保持原行为。V16 的行为核实不承担原抽取记录的对应证明，新关联协议单独区分，不能改变历史 V16 回复的含义。

私有核实记录把原记录、实际接纳的新路径、关联核实请求和最终观察联系起来。保存时核对真实的冻结来源、角色设定和观察；摘要长得像一个有效标识并不等于来源已经证实。普通报告继续展示问题、待复核和原文，不暴露内部标识、模型回复或账户凭据。

## 验证边界

工程验证覆盖正常关联、含义不等价或不确定、来源错配、旧任务兼容、共享调用额度及实际保存流程。真实试用复用已确认的角色基线和不变原稿，按正常作者操作新增一次审查，明确标为已知开发问题修复验证。

实际是否调用新协议、是否解除疑点，以及最终报告分别记录，不以必须得到正式问题作为通过条件。首轮真实稿自然抽出了非空物件，未进入 V17；这条结果保留，并据此修正入口条件，而非改写原记录让它进入指定分支。具体构建与结果见[当前阶段状态](current-stage-status.md)，不作为独立准确率。
