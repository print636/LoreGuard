# 单次审查中的物品去向与交接

日期：2026-11-10。起点 `9c46cb3`。当前为实施合同，验收结果在完成后补充，不作为已交付记录。

## 已确认的作者需求

用户先选择物品去向与交接，再确认查询范围为选定一份审查报告所包含的剧情与设定。首批回答“谁在何时持有／保管／使用、怎样交接、依据在哪”，不自动拼接不同报告的版本或分支。

## 首批行为

- 从现有作品工作区的关系与时间入口进入物品去向，不要求先生成关系图或时间线。
- 搜索报告内物品名称，选择后查看与该名称相关的持有、保管、明确未交接、转交和使用记录。
- 每条交接显示双方人物、原文时间和来源；有已保存的时间关系支持时，展示可确定的先后与断点。
- 摘要以具体来源事件为依据，显示最后一条可确定的持有／使用记录及其时点；无法确定先后时不选定一个“最后持有人”。
- 明确记载与已有依据支持的推断分别显示。看到持有或使用不自动补成交接；物理保管不等于法律所有权。
- 点击普通记录也能读该次审查冻结的完整原文，零正式问题不影响使用。复用既有阅读器的权限、版本和内容校验。
- 来源已有新版时，沿上一阶段展示变化提示并可进入复检准备；查询本身只读，不发模型、写旧结果或自动收费。

名称是本次报告中的检索分组，不单凭同名证明所有记录属于同一物理对象。不同故事范围不自动串联；不确认的别名不模糊合并。旧记录没有新来源证明时，可以阅读原记录与出处，但不能补造新认证。

## 有用结果与边界

普通明确交接应能让作者看清每一次 X 交给 Y、相关原文时点及有依据的先后；不能只将原始字段换一种排版，也不能因为无法证明永久同一而把每个明确事件都笼统写成未知。

“最后一条有据记录”不等于此后始终持有、全书当前状态或全部事实已经穷尽。上传时间、文稿版本和章节排列不自动代表故事发生顺序，同一钟点不自动代表同一天。当前不提供任意“截至第 N 章”的状态推演，不跨报告汇总状态，不覆盖原审查问题或作者确认。

本阶段优先复用已有物品语义、已持久化的来源证明与有界时间范围，无新增状态数据库或模型判决层。若实现确实需要修改模型抽取或比较，先说明共同缺口与范围，再安排限定真实验证；不逐个适配罕见措辞。

合计条件工作量为 22–32 小时。后端与前端合同对齐后并行，验收准备提前进行，不能把三线小时数相加当作顺序等待。它们不是已计量工时或固定完成时间；不以 CI 排队、Git 时间差换算劳动工时。已有十四处用户修改及原数据持续保护。

## 验收方法与停止线

优先复用已有普通真实模型报告：合法铜钥匙交接链检验明确结果，综合星钥稿检验持续保管与时序未知能否如实展示。它们是已知开发材料，不是新盲测。若本批没有修改模型链路，不为查询展示重跑模型；如确需改动，固定代码、原文和配置后最多各运行一次，保留全部结果。

开发中只做必要的相关专项；稳定后一次集中体验审查，多项问题合并修复，再补受影响路径及最终 CI。普通账户应可选择报告、查物品、理解明确经过或未决、打开冻结原文、看到来源变化并自主准备复检；桌面和窄屏都可操作。

交付这一有界查询闭环后进行阶段对齐。更完整的对象同一性、跨报告状态、任意章节截止查询、角色知情、外部 AI 协议与公网容量均不随本批自动启动。
