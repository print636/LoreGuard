固定构建 `230258a5a66cefc0800419c165c868126e682a39` 新增默认关闭、只观察不改变判定的 `character_signal_support_trace_v1`。它仅在 V4 断言 ID 协议开启时记录正式角色设定：模型包是否提交过匿名断言槽、每次尝试的固定拒收原因、以及最后一个干净模型包中接受的槽。它不保存原文、人物、文档名、真实行号、原始模型回复、密钥或服务地址；候选形成无法逐条安全关联，明确报告 `candidate_transition=unavailable`。无法解析的包标为不可观察，不推断“模型未提交”。正常产品开关仍为关闭；该诊断没有放宽角色归属、核心/稳定标签或候选准入。

在预先固定、开发者可见的 [character-axis-challenge-v2](../data/character-axis-challenge-v2/manifest.json) DEV 材料上，本机配置的 `deepseek-v4-pro` 经隔离 HTTP 服务完成了三次独立项目诊断。V2、V3、V4 和本诊断同时开启；三轮报告的构建哈希、服务构件哈希及基线任务运行来源摘要分别一致，但完整双阶段 API-worker 来源门槛未适用。每次基线有 10 次逻辑模型调用、6 个可用的正式设定匿名轨迹块。三次都在 `baseline_admission_failed` 停止，正式背景覆盖均为 `partial`，各产生 3 个计划外可审核候选，冻结的五个候选选择器 **0/5** 匹配；草稿未上传、未审查。总计 **15 个预设新稿案例未评**，因此没有 OOC 精确率、召回率或误判率。严格 `provenance_gate` 因缺少新稿任务不适用，不能宣称完整双阶段来源门槛通过。

上述五个目标的相关模型包均可解析，断言索引与同版服务器分块逐一核对，故这里的“未提交”不是非法 JSON 造成的未知。但它仍**不表示模型看不懂该事实**：模型可能按提示选择省略、未把它视为独立稳定设定，或被上下文及输出上限影响。`character_support` 则只说明模型提出的记录未通过当前服务端角色归属校验，**不证明模型归属一定错，也不证明服务端一定错**。同版静态检查还表明，S1–S5 的目标分句本身均未明示目标角色，现行 V4 直接主语守卫对五项都会拒收；即使让模型补交 S1/S4/S5，也不会自动成为合格基线。因此观察到三项未提交，并不能将基线失败主要归因于模型漏抽。每次还有 11 个 `character_support` 拒收/重试事件；它们是模型包尝试事件，不是 11 条独立人物事实。没有保存模型原句，不能从该原因码反推模型实际写了什么。

本材料的五个目标引文均在来源行的后续分句，目标分句缺明示角色；核心或稳定标签位于前一分句。冻结审核计划预期它们进入正式档案，但“前一分句标签是否覆盖后一分句”尚未由独立作者确认。服务端不能因为“同一行”就自动继承角色与标签，否则他人言行、转述、问句、假设或转折也可能被错误晋升。当前已证实的是**评测材料期望与服务端局部断言准入存在结构性冲突**；模型对这类跨句含义的推理能力尚未被单独测到。

一些单元测试故意给出错误结构化记录，例如把复合对象截成前缀或把正向偏好标为负向，用来证明服务端会拒绝这类输出。这是人工构造的防线测试，**不是**真实模型错误发生率。相反，本页的三次 HTTP 运行是真实模型调用，但因为全停在基线阶段，也**不是**实际 OOC 判断成绩。另有一次 Windows 本机运行在启动基线后、生成报告前中断；其未完成试次已排除出三次有效诊断，故障数据库单独保留且未混入重试。脱敏 JSON 留在 Git 忽略的 `artifacts/axis-trace-v1-dev-{1|2|3}-230258a.json`，不上传剧情正文或模型回复。
