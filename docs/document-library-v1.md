# 资料库与文稿阅读 V1

状态：已实现。人工双人封闭评测由用户暂缓，本阶段补齐日常资料阅读流程，不修改 OOC 判定。

## 使用场景

游戏剧情策划需要核对某次活动或章节的旧稿，网文作者需要查找历史段落并比较当前稿。
资料库按同名文稿整理版本，让作者选择实际存储的版本、阅读原文、按文字查找，再进入
现有版本差异页。上传、资料身份确认与作者定稿发布继续使用已有入口。

本阶段不增加正文编辑、版本恢复、删除、自动发布或自动修订。

## 界面与操作

- 左侧为文稿目录，可按文件名、资料类型和当前/历史版本状态筛选，每页 20 份文稿。
- 右侧选择版本后按需读取正文，每页 120 行，行号与后端证据定位一致。
- 原文搜索为字面匹配，显示匹配的原始行号；清除搜索后恢复全文阅读。
- 历史版本可与同名当前活动版本比较，复用已有确定性行级差异接口。
- 本次会话中从差异页返回资料库，保留目录筛选、页码和版本选择；正文不写入浏览器存储。
- DOCX 显示导入后保存的文字内容，Word 的排版、批注和图片不由阅读器还原。
- 目录与正文各自有界滚动，列表分页不藏在滚动区内；手机选稿后定位阅读标题。
- 资料库页面不展示旧审查报告侧栏，将可用宽度留给文稿阅读；审查页与报告页保持原布局。

沿用 `design-system/loreguard/MASTER.md` 的星轨书斋设计：紫青语义色、安静的正文区、
有分隔的目录行，手机按单列排列。资料阅读不使用“开始校验”的彩色渐变按钮。

## 只读接口

`GET /api/v1/projects/{project_id}/documents/{document_id}/preview`

查询参数：`offset >= 0`、`limit=120`（最大 200）、`query`（最长 160 字符）。

响应：

```text
document: 文档元数据 + char_count / line_count / content_sha256
lines: [{ line_number: 原始 1-based 行号, text: 原文行 }]
page: { offset, limit, total, has_more }
query: 去除首尾空白后的查询
```

无查询时对全部原文行分页；有查询时按逐行 `casefold` 字面子串匹配，`page.total` 为
匹配行数，`line_number` 始终使用原始行号。搜索不解释正则表达式，也不调用模型。
正文分行与已有证据使用同一 `splitlines()` 规则，保留中间空行。

接口同时校验工作区、项目与文档归属，允许读取已失活的历史版本；无法访问的项目或
文档统一返回 404。正文响应使用 `Cache-Control: no-store`。读取不修改正文、资料上下文、
发布状态或分析任务。

## 验证范围

2026-10-02 阶段集中验证：

- 后端预览与现有版本差异测试：45 项通过，使用独立临时数据库验证历史版本、分页、
  字面搜索、原始行号与工作区隔离，拦截数据库写入、Provider 与分析调用。
- 前端业务单测：187 项通过，其中 9 项为资料库 helper；TypeScript 与 Vite 生产构建通过。
- 新增浏览器任务覆盖旧稿阅读、精确比较与返回、分页和字面搜索、迟到响应、失败恢复、
  空状态、键盘及 360/1440 布局，全部 5 项通过；流程没有发送 POST。
- 原有作者发布浏览器回归：3 项通过，资料阅读不会替作者发布。

目录分页目前基于已有元数据列表在前端进行；后端正文按行分页，但每次查询仍需扫描
该版本正文。这里不宣称数据库级大规模目录分页、全文索引或超长稿性能已经完成。

模拟用户与 Mock API 浏览器验证只说明这一产品流程的行为；OOC 人工封闭评测仍等待
两份独立真人标注，本阶段不生成或揭示其答案。
