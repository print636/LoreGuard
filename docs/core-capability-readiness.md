# 常用能力覆盖与阶段验收

本阶段按通用能力整理 LoreGuard，并用一组普通作者材料验证。具体故事是发现共性问题的手段，不为每个角色、物品名称或特殊写法单独扩展规则。特殊叙事、超长篇和需要专门领域知识的情况留待后续维护。

首轮产品代码固定在 `72e05b8`，相同功能代码为 `cc0e5a7`。首轮暴露共同的调用等待限制后，另行集中修复；原始结果与后续恢复批分别记录。本表区分三件事：产品已有入口、受控工程验证通过、真实模型在某份材料上的表现。前两者不能替代第三者，少量开发稿也不能证明开放故事的准确率。

## 本批验证方法

1. 优先使用已公开的普通开发材料，预先固定材料、预期范围、作者选择、运行代码和模型。答案只用于运行后对照，不送入模型。
2. 选择精简的一组新运行，兼顾明确冲突、正常无冲突或合理解释、材料不足。包含多章正文及一组原稿到修订稿的复检；修订稿是不同输入，不是对原稿重复采样。
3. 走普通账户和作者接口，保留全部候选，再按材料含义及预先声明的选择范围确认。候选缺失或含义无法确认时记为未完成，不制造基线让任务继续。
4. 分开记录模型是否实际参与、材料覆盖、正式问题、待复核、证据是否可定位及工作流是否完成。未运行、未评估和确认无冲突不能合并。
5. 同一配置下每份固定输入只运行一次。批次结束后按原因集中整理问题，再决定是否存在值得本阶段修复的共性阻断。确有产品修复时，只对受影响输入做明确标注的修复后回归，保留原失败，不反复采样挑结果。没有实际问题就不新增功能或协议。

本批是开发回归与产品可用性观察，不是新的独立人工盲测。原人工封闭集的成绩与使用边界保持原记录；已经用于诊断或开发的材料，不能通过换一次运行就重新称为独立验收。

## 修复优先级与结束条件

优先修复常用流程跑不通、错认主体或对象、无充分证据却形成正式问题，以及同一原因影响多类材料的缺口。少见但会损坏数据或破坏账户隔离的问题仍须处理，不能仅因频率低而延期。罕见叙事方式、特定文风和单一措辞兼容性先记录，不作为当前阶段不断延期的理由。

结束时必须给出本批实际结果及剩余限制。若主要能力仍有未完成判断，应明确指出影响哪类正常使用；若主要流程与常用能力已经通过本批检查，则转入作者实际使用、反馈和学习准备，不追求穷尽所有故事场景。

## 本批结果

### 首轮：建档完成，审查遭遇运行障碍

使用 `gpt-6.1-sol`，六份人物资料均完成建档，共形成八项可供作者确认的候选，涵盖性格、偏好、习惯、适用情境、成长前状态和行为边界。候选与资料语义相符；这只证明本批建档结果，不证明新稿判断能力。

事实原稿任务耗时约 62 秒。一次逻辑抽取内的两次 HTTP 尝试均在等候响应头 30 秒后超时，没有取得模型正文或用量回执；随后系统仅完成确定性预检。正式问题为零，但本轮事实审查**未完成**，不能算正确排除了矛盾，也不能把无 Token 回执解释为上游没有消耗。两章冻结来源与输入一致。

其余六份人物新稿因批次驱动读取文件时遗漏 `.json` 扩展名而未启动，未创建分析任务、未向模型发送新稿。这个准备脚本错误与产品判断能力分开记录；保留原始阻断记录，在独立恢复驱动修正，不重新建档或修改故事输入。

### 共用修复与恢复范围

30 秒限制来自产品默认值，部分角色步骤还存在独立的短上限。单改测试脚本不能改善普通作者使用，因此集中调整本机模式的有界等待配置，并让多步骤共享整次任务的截止时间。该修复不改提示词、故事判断规则、模型调用次数或重试次数。

恢复批复用原六份真实基线、八项候选和全部冻结文本，运行尚未执行的六份人物新稿及固定事实修订稿。另外对唯一受等待配置影响的事实原稿做一次修复后回归，明确标注产品与配置变化；原始超时仍然保留，若回归再次失败也不追加采样。

原稿的修复后回归与固定修订稿可以共同观察发现问题、反馈、修改、复检和发布流程。若原稿仍未完成判断，修订稿即使顺利完成，也不能据此宣称三个冲突已被系统发现并修复。后续结果不作为新的独立盲测。

### 恢复批确定的共性修复顺序

1. **先防止同句多特征串用。** 一次判断只能针对当前作者确认的那条设定；同一来源句的其他特征可作为上下文，不能偷换成正在审查的目标。目标编号匹配和引用正确仍不足以证明语义对齐，也不能只用去重隐藏误报。
2. **补普通叙事中的时间与知情约束。** 本批两条“12:00”的异地事件已经抽取保存，但当前规则要求完整年月日，正文明确同日的信息没有参与比较。知情规则还需要区分实际获知时间与“某时之前明确不可能得知”的约束，不能伪造一次实际获知事件。按通用时间关系建模，不为角色名或故事写特例。
3. **区分同一段落中的行为与解释断言。** 当前同一物理行的复合材料会被限制为可能解释，医嘱与拒食即使是不同断言，也不能进入已核实的例外。这是材料划分和接纳方式的共性限制；后续应核实具体片段、因果与时序，避免靠换行改变判断，也不能直接把行为本身当作其解释。

内部失败缺少安全错误分类，作为通用可诊断性缺口一并跟进；不通过新增一批刁钻故事追查。罕见表述、超长篇和专用分支暂缓。本阶段完成调用预算修复、同版本能力盘点和真实工作流观察，**没有达到“常用场景全部验证通过”的结论**。

本次共用修复的受控验证覆盖共享期限、重试与 fork 不续时、旧任务兼容、取消与租约接管，以及模型回包后中断仍保存已报用量。一轮集中审查定位用量遗漏后，仅补受影响验证；[五项 CI](https://github.com/print636/LoreGuard/actions/runs/42080777663) 全部通过。工程检查通过与上表中的语义缺口分别记录。

## 增量修复：判断当前具体设定

功能 `4988b25` 接续上面的第一优先级。在已有抽取和主审中传入作者确认的完整表述，并区分目标支持断言、同句其他内容与完整上下文；缺少描写不能成为正式反例。有证据的语义推断仍被允许，未增加一层模型判决。报告同时标明正在对照的具体设定，旧任务和报告保持原义。

复用同一真实黎音基线、两项确认和同一原稿，只新增一次修复后审查：原“主动长谈”冲突保留为正式问题；“先观察”不再借用另一条特征判断，改为证据不足的待复核。实际为 1 正式、1 待复核，仍部分覆盖，不能把这条线索或整稿说成已经确认无问题。

另用一份预先固定的普通稿明确写“没有先观察对方”，同基线下一次审查得到该目标的 1 项正式问题，证明本轮没有靠全部拒绝“先观察”目标来减少误报。另一条长谈设定没有匹配观察、未进入主审，不计为已审无冲突。两稿分别耗时 118.0 和 91.5 秒，未重新建档、改变模型或重采样；原有错误报告保留。

两稿原文入口、来源与公开内容已核对。受控测试覆盖目标串用、明确反例、同义推断、缺少描写、旧策略兼容及私有字段投影。这是固定公开开发稿的修复回归，不是独立盲测或整体质量结论；相应实现和结果见[当前阶段记录](current-stage-status.md)。

本轮另外补了内部失败的安全异常类型及固定阶段分类，没有重跑或宣称修复上一批代词稿的未知根因。随后按上述顺序补通用时间与知情约束，结果如下。

## 增量修复：普通时间与知情约束

功能 `1617ad2` 在原有一次抽取中增加有来源的直接时间关系和知情约束，不新增模型层。服务端为普通新任务冻结能力，旧重试保留原行为。明确同日或先后关系可以用于比较；同一钟点、同一主线、后来读到某信息，单独都不能证明同一天或此前一定不知情。

固定原稿与修订稿通过普通作者接口各运行一次，模型仍为 `gpt-6.1-sol`。原稿 50.0 秒得到两项正式问题：星钥持有冲突保留，同日同刻异地新增命中，双侧原文及同日依据可读。修订稿 39.1 秒没有正式问题。两次分别有 3 条和 1 条词面支持未决记录，均为部分覆盖，因此仍不能声称整稿审查充分或修复已被完整证明。

两稿的知情记录均保留了渠道受限与已表现知情的区别。模型把“未看过密令、未听说坐标”归为渠道限制，规则没有将它升级为全局未知；本批没有知识正式问题，也没有虚构获知时间。这验证了接线及保留边界，知识正式命中的规则验证仍来自受控测试，不能表述为真实正文效果已全部通过。

本轮保留了被拒记录的安全字段及来源位置，因此能区分原因：原稿从口袋取出的持有记录、无系词的“北门敞开”状态受既有词面限制；两稿各一条假设段落被抽为开放问题，原文缺少疑问表达，拒收该类型合理。不能把所有拒绝归因于模型，也不能只消除覆盖提示而放行未经核实的记录。

后续验收提交 `b3b8a93` 只适配旧测试、Compose 示例合同及指南，业务代码和真实受测版本保持一致。[五项 CI](https://github.com/print636/LoreGuard/actions/runs/42196904129)全部通过；浏览器环境安装触发一次总时限后，仅同提交该任务重试，未重跑真实样本。这是公开开发材料的功能回归，仍不是新的人工盲测成绩。

随后处理**同段落内独立断言的来源粒度**，结果见下方。词面拒收的具体原因继续保留，按共同障碍而非逐个故事模板安排修复；不展开罕见场景或无限因果推理。
