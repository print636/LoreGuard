# 潮镜站角色 OOC 开发挑战集 v1

这套四文档、三角色的简体中文剧情全部原创。它检验“角色稳定设定 + 已发布成长经历 + 新版本活动稿”的证据闭环，不是人工盲测，也不是生产准确率样本。所有材料位于主时间线；前三份为正式背景，第四份为低权威待审新稿。

预先标注的三个目标：南枝在两个独立时段主动与陌生人长谈，缺少相关成长/任务解释，属于需要证据复核的核心性格偏移；郁礼虽从退缩变得善于公开讲解，但已发布章节提供连续训练依据，不应报确定冲突；岑烛只因即时安全警报厉声打断一次，不应被判定为稳定人格改变。

这套样本是 **DEV 挑战集**。可以据此修复通用提取或裁决缺陷，但不能在调过后宣称它是未见 holdout。运行时只将故事文档交给模型，`acceptance-oracle.json` 仅由评测器在输出后读取。后续应另建冻结且从未调参使用的世界观进行验证。

首次 DEV 探针后修正了一个标注方向问题：模型可能以“克制打断”为正向比较轴，也可能以“打断行为”为负向比较轴。两种 `trait_key + polarity` 配对语义相同，单独限定 `polarity` 会错误拒绝其中之一。Oracle 现在只接受这两个成对选项，不允许交叉组合。该标注修正不改变故事正文；从此样本获得的结果仍只属于开发诊断。

2026-09-23 后续 DEV 运行还发现，郁礼的档案原句是“早期稳定的性格状态”，并未明确称为“核心性格”。旧 Oracle 要求 `stability=core` 比原文更强，导致证据绑定正确的 `stable` 候选被拒。现将该候选限定改为 `stable`；这是观察模型输出后的标注修正，不使本集获得独立评测资格。先前失败产物保留，不以此改写旧结果。

`scripts/run_character_consistency_live.py --fixture ooc-v1` 将通过 HTTP 新建独立项目并真实调用 Provider，需要服务已开启角色一致性。默认三轮完整流程会消耗模型 Token；可先 `--trials 1` 做诊断，但单轮不能通过该 runner 的三轮稳定性门槛。脱敏结果保存在 Git 忽略的 `artifacts/` 内。

若基线模型产生不受原文支持的额外记录，严格运行会停在基线准入并记录 `partial`。开发阶段可额外使用 `--diagnostic-continue-partial-baseline` 观察候选确认和新稿裁决；**部分覆盖的完整性 gate 仍为 false**，这样的输出不能用作通过验收的证据。此参数只对 OOC 开发集生效，不改变产品的模型证据门或历史演示集门槛。
