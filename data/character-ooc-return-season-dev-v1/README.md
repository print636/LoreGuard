# 善潮号·回港季｜角色连续性 DEV 挑战集

这是一套完全原创、可公开的开发者可见合成素材，不含商业游戏剧情、用户稿件或公司资料。它用于设计与排查“已确认角色设定 + 已发布版本剧情 → 新版本活动稿”的角色一致性审查，不是人工盲测，也不证明当前模型已经达到这些预期。

按顺序导入 `01-world-setting.md`、`02-character-profiles.md`、`03-published-main-v1.0.md`、`04-published-main-v1.1.md`，最后以 `05-draft-event-v1.2.md` 作为待审新稿。世界设定和角色档案需由作者确认；v1.0、v1.1 是主线已发布历史，v1.2 是未发布活动稿。所有素材都在同一主线，没有互斥分支。正式候选仍须经过作者逐条审核和确认，不能因为本目录附带答案就自动晋升。

`manifest.json` 记录建议导入角色、版本、发布状态和作用域，不代替用户在产品中确认资料。`oracle.json` 预注册五个潜在 OOC 轴和六个不应误报的对照场景。`review-plan.json` 只给出作者拟审核的五条稳定比较轴与源证据，并非真实用户已完成的确认记录。新稿中的 `【Dxx】`、正式资料中的 `【Axx】`、`【Hxx】` 等编号是稳定片段标识；评测器应以冻结文档中的实际原文和行号绑定，不应仅靠编号、关键词或本目录的 Oracle 作模型输入。修改素材后须另起版本，不把调试后得到的答案伪装成冻结测试集。

五个正例是五条不同的角色价值或行为边界：避风席位公平、变更告知、病史授权、预报不确定性、原始数据完整性。每个正例都有两次相互独立的反向行动，不能把同一连续动作拆成两条凑数。六个负例覆盖紧急伤情分流、伪造语音、受众受限的授权、匿名紧急通报、他人篡改，以及已发布事件解释的方法变化。

严格评价时要区分三件事：模型是否抽到候选、服务端是否接受且正确绑定双侧证据、完整材料下是否给出恰当判定。模型或证据阶段部分降级时，不能把“没有可见问题”计为负例正确，也不能把潜在 OOC 的缺失计为审查通过。五个正例最终可按五条轴聚合，但不得把故事片段数误当成问题数。

现实策划项目中，警报是否构成迫近危险、许可覆盖的具体内容与受众、匿名信息是否仍可重新识别、伪造音频的取证可靠性，以及角色变化是否已有充分铺垫，都需人类策划最终裁决。本合成集把这些条件明确写死以供 DEV 排障；不代表系统能从任意开放文本自动获得同等确定性。
